    13→   512→   512→## 7. Sync Engine (`src/lib/sync-engine.ts`)
    14→   513→   513→
    15→   514→   514→### Trigger points
    16→   515→   515→1. **App startup** — fires once Dexie is initialized.
    17→   516→   516→2. **Offline → online transition** — `use-online-status` hook notifies the engine.
    18→   517→   517→3. **Periodic** — runs every few minutes while online.
    19→   518→   518→
    20→   519→   519→### Algorithm
    21→   520→   520→```
    22→   521→   521→1. Acquire mutex (in Dexie.syncMeta) — prevents concurrent syncs across tabs.
    23→   522→   522→2. Read lastSyncTimestamp from syncMeta.
    24→   523→   523→3. GET /api/sync?since=<lastSyncTimestamp>.
    25→   524→   524→4. For each chemical in response:
    26→   525→   525→   - If deleted (deletedAt > since) → remove from Dexie.chemicals.
    27→   526→   526→   - Else → upsert into Dexie.chemicals.
    28→   527→   527→5. For each sdsDocument in response:
    29→   528→   528→   - Upsert metadata into Dexie.sdsDocuments.
    30→   529→   529→   - Compare version with Dexie.sdsBlobs.
    31→   530→   530→     - If version unchanged AND blob exists → skip (no re-download).
    32→   531→   531→     - If version changed OR blob missing → GET /api/sds/[id]/download,
    33→   532→   532→       store Blob in Dexie.sdsBlobs with new version.
    34→   533→   533→6. Persist new lastSyncTimestamp = response.serverTime.
    35→   534→   534→7. Release mutex. Update Zustand sync status.
    36→   535→   535→```
    37→   536→   536→
    38→   537→   537→### Rate limiting
    39→   538→   538→A minimum interval between sync attempts prevents hammering the server on flaky connections. Manual retry from the UI bypasses the interval once.
    40→   539→   539→
    41→   540→   540→### Status states (the `SyncStatus` type)
    42→   541→   541→| State | Meaning |
    43→   542→   542→|---|---|
    44→   543→   543→| `offline` | Navigator reports offline. No sync attempts. |
    45→   544→   544→| `syncing` | A sync is in progress. |
    46→   545→   545→| `synced` | Last sync completed successfully and we're online. |
    47→   546→   546→| `local-changes` | *(reserved)* user has local-only changes that couldn't be pushed (currently preferences only — always local). |
    48→   547→   547→| `error` | Last sync attempt failed. UI shows a retry button. |
    49→   548→   548→
    50→   549→   549→### Conflict resolution
    51→   550→   550→- **Chemical / SDS data:** server-wins. The latest `updatedAt` always wins.
    52→   551→   551→- **User preferences / favorites / notes:** local-only, never synced, never overwritten.

    56→   555→   555→## 8. Security Model
    57→   556→   556→
    58→   557→   557→### Authentication
    59→   558→   558→- NextAuth Credentials provider.
    60→   559→   559→- **3-tier role hierarchy**: `SUPER_ADMIN` > `ADMIN` > `USER`. Only `SUPER_ADMIN` and `ADMIN` can sign in to `/admin/*`; `USER` is reserved for the public PWA and is rejected by `authorize()`.
    61→   560→   560→- Disabled accounts (`disabled === true`) cannot sign in.
    62→   561→   561→- Passwords hashed with **bcrypt (12 rounds)** — never stored or logged in plaintext.
    63→   562→   562→- JWT session strategy, 30-day max age. The JWT carries `id`, `role`, and `passwordChangeRequired`; the `session` callback copies them onto `session.user`.
    64→   563→   563→- On `useSession().update()` (trigger `"update"`), the `jwt` callback re-fetches `passwordChangeRequired` + `role` from the DB so a just-completed password change is reflected without a fresh sign-in.
    65→   564→   564→- Cookies: `httpOnly`, `sameSite=lax`, `secure` in production (`__Secure-` prefix).
    66→   565→   565→
    67→   566→   566→### Authorization (defense in depth)
    68→   567→   567→1. **Edge middleware** (`src/middleware.ts`) — blocks `/admin/*` (except `/admin/login`) unless the JWT has `role === "SUPER_ADMIN" || role === "ADMIN"`. Fast, runs at the edge. (Super-admin-only routes enforce the stricter check server-side via `requireSuperAdmin()`.)
    69→   568→   568→2. **`requireAdmin()`** (in `src/lib/session.ts`) — every admin API route for chemicals / SDS / dashboard / change-password-adjacent features calls this. Returns 401 if the session is missing or the user is not `ADMIN` / `SUPER_ADMIN`. **Also returns 401 if the user has `passwordChangeRequired === true`** — defense-in-depth so a bypassed client guard still can't reach the API.
    70→   569→   569→3. **`requireSuperAdmin()`** (in `src/lib/session.ts`) — same shape as `requireAdmin()` but additionally requires `role === "SUPER_ADMIN"`. Used by user-management, audit-log, and system-settings routes. Also blocks `passwordChangeRequired` users.
    71→   570→   570→4. **`PasswordGuard`** client component (`src/components/admin/password-guard.tsx`) — mounted in the admin layout. Uses `useSession()` + `usePathname()`; if the current path is NOT `/admin/login` and NOT `/admin/change-password`, and the session has `passwordChangeRequired === true`, hard-redirects to `/admin/change-password`.
    72→   571→   571→
    73→   572→   572→### Audit log
    74→   573→   573→Every chemical / SDS / user / system mutation is logged via `logAction()` in `src/lib/audit.ts`.
    75→   574→   574→- **Fire-and-forget**: `logAction()` wraps its `db.auditLog.create()` in a `try/catch` and only logs to `stderr` on failure. An audit-log problem can **never** break the main operation the user is trying to perform.
    76→   575→   575→- **Captures**: `actorId`, `actorEmail` (denormalized so the row survives user deletion), `action` (dotted, e.g. `chemical.create`, `user.disable`, `system.test-ai`), `entityType`, `entityId`, `summary`, `before` / `after` JSON snapshots (built via `snapshotChemical()` for chemicals), and a best-effort `ipAddress` (from `x-forwarded-for` / `x-real-ip` via `auditContext()`).
    77→   576→   576→- **Storage**: `AuditLog` table (append-only — no update / delete endpoints exist). Indexed on `createdAt`, `actorId`, `[entityType, entityId]`, `action`.
    78→   577→   577→- **Viewer**: `GET /api/admin/audit` (SUPER_ADMIN only), cursor-paginated. UI: `src/components/admin/audit-log-viewer.tsx`.
    79→   578→   578→
    80→   579→   579→### Password change enforcement (triple-layered)
    81→   580→   580→When a super-admin creates a user with a temporary password (or resets an existing user's password), `passwordChangeRequired` is set to `true`. The user is then forced to change their password on next login via three independent layers:
    82→   581→   581→1. **Client-side guard** — `PasswordGuard` (`src/components/admin/password-guard.tsx`) redirects to `/admin/change-password` as soon as the session loads. Bypassing this is possible (disable JS), so it's UX + first line of defense only.
    83→   582→   582→2. **Server-side guard** — both `requireAdmin()` and `requireSuperAdmin()` return 401 when `passwordChangeRequired === true`. So a user with the flag set cannot call any admin API route except the change-password endpoint.
    84→   583→   583→3. **Verified current password** — `POST /api/admin/change-password` calls `getServerSession` directly (NOT `requireAdmin()`), verifies `currentPassword` against the bcrypt hash, rejects if `newPassword === currentPassword`, hashes the new password, sets `passwordChangeRequired=false`, and audit-logs `user.password-change`. The client then calls `useSession().update()` so the JWT refreshes without a fresh sign-in.
    85→   584→   584→
    86→   585→   585→The change-password route is the **only** admin API route that does not go through `requireAdmin()` / `requireSuperAdmin()` — by design, so the flag-bearer can still escape the gate.
    87→   586→   586→
    88→   587→   587→### SDS file upload safety
    89→   588→   588→- **Magic-byte validation** — the file must start with `%PDF-` (PDF signature). Renamed non-PDFs are rejected.
    90→   589→   589→- **MIME type check** — must be `application/pdf`.
    91→   590→   590→- **Extension check** — must end in `.pdf`.
    92→   591→   591→- **Size limit** — enforced (see `validation.ts`).
    93→   592→   592→- **Filename handling** — user-supplied filename is stored only for display/download. The actual stored file is named `<uuid>.pdf` under `storage/`. No path traversal possible.
    94→   593→   593→- **No path exposure** — `storageKey` is a UUID, never the original path.
    95→   594→   594→
    96→   595→   595→### Input validation
    97→   596→   596→- All admin chemical inputs validated with **zod** schemas before reaching Prisma.
    98→   597→   597→- Prisma parameterizes all queries — no raw SQL, no SQL injection surface.
    99→   598→   598→
   100→   599→   599→### Security headers (`next.config.ts`)
   101→   600→   600→- Content-Security-Policy
   102→   601→   601→- X-Frame-Options: DENY
   103→   602→   602→- X-Content-Type-Options: nosniff
   104→   603→   603→- Referrer-Policy
   105→   604→   604→- Strict-Transport-Security (HSTS)
   106→   605→   605→- Permissions-Policy
   107→   606→   606→
   108→   607→   607→### Secrets
   109→   608→   608→- `NEXTAUTH_SECRET` — required in production. Generate with:
   110→   609→   609→  ```bash
   111→   610→   610→  bun -e 'console.log(require("crypto").randomBytes(32).toString("hex"))'
   112→   611→   611→  ```
   113→   612→   612→- `ADMIN_PASSWORD` — plaintext in `.env` only; hashed before DB storage.
   114→   613→   613→- `.env` is gitignored. `.env.example` is the committed template.
   115→   614→   614→
   116→   615→   615→### Known platform-level caveat
   117→   616→   616→The sandbox gateway (`Caddyfile`) uses an `XTransformPort` query param for port routing. This is an open-proxy-style SSRF surface at the **infra level** and is outside the application code. Flag for the platform team before any public deployment.

   245→   744→   744→4. Add new `require<Role>` helpers in `src/lib/session.ts` as needed (mirroring the shape of `requireAdmin()` / `requireSuperAdmin()`) — including the `passwordChangeRequired` block for defense-in-depth.
   246→   745→   745→5. Add role-based checks (or zod enum extensions for `role` in `createUserSchema` / `updateUserSchema`) in the relevant API routes. The user-manager UI (`src/components/admin/user-manager.tsx`) also has a hard-coded role Select that may need the new option.
   247→   746→   746→
   248→   747→   747→### Change the sync interval
   249→   748→   748→Edit the periodic interval constant in `src/lib/sync-engine.ts` (and/or `src/hooks/use-sync.ts`).
