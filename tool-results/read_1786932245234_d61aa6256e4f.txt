     9→## 0. Quick Start — How to Run This Project
    10→
    11→> Read this section first. It covers everything from a fresh `git clone` to a running app.
    12→
    13→### 0.1 Prerequisites
    14→
    15→| Requirement | Why | Install |
    16→|---|---|---|
    17→| **Bun** (required) | The `db:seed` script and production `start` script run TypeScript / the standalone server via Bun. npm/node alone will **not** work. | https://bun.sh/docs/installation |
    18→| **Node.js 18+** | Next.js 16 needs it. Bun usually bundles a compatible runtime, but having Node helps with tooling. | https://nodejs.org/ |
    19→| **Git** | To clone the repo. | https://git-scm.com/ |
    20→
    21→> **Windows users:** Install Bun with PowerShell (`irm bun.sh/install.ps1 | iex`). All commands below work in **Git Bash** or **WSL**. If you only have CMD/PowerShell, the `dev` script still works (it's just `next dev -p 3000`), but `db:seed` needs Bun regardless.
    22→
    23→### 0.2 Step-by-Step (fresh clone)
    24→
    25→```bash
    26→# 1. Clone the repository
    27→git clone <your-repo-url> sds-chem
    28→cd sds-chem
    29→
    30→# 2. Install dependencies with Bun (do NOT use npm install)
    31→bun install
    32→
    33→# 3. Create your environment file from the template
    34→cp .env.example .env
    35→
    36→# 4. Edit .env — set these values:
    37→#    - ADMIN_EMAIL         (your admin login email)
    38→#    - ADMIN_PASSWORD      (a strong password — will be bcrypt-hashed)
    39→#    - NEXTAUTH_SECRET     (generate one — see the comment in .env.example)
    40→#    - DATABASE_URL        (already set to ./db/custom.db — leave as-is)
    41→#    - NEXTAUTH_URL        (already http://localhost:3000 — leave as-is)
    42→#
    43→#    Generate a NEXTAUTH_SECRET with:
    44→#      bun -e 'console.log(require("crypto").randomBytes(32).toString("hex"))'
    45→#      node -e "console.log(require('crypto').randomBytes(32).toString('hex'))'"
    46→
    47→# 5. Create the SQLite database + tables
    48→bun run db:push
    49→
    50→# 6. Seed the database:
    51→#    - Creates the admin user from ADMIN_EMAIL / ADMIN_PASSWORD
    52→#    - Imports the 14 seed chemicals
    53→#    - Generates a placeholder SDS PDF for each chemical
    54→bun run db:seed
    55→
    56→# 7. Start the dev server
    57→bun run dev
    58→```
    59→
    60→Open **http://localhost:3000** in your browser. You should see the chemical catalog with 14 chemicals.
    61→
    62→### 0.3 Accessing the admin dashboard
    63→
    64→1. Go to **http://localhost:3000/admin/login**
    65→2. Sign in with the `ADMIN_EMAIL` / `ADMIN_PASSWORD` you set in `.env`.
    66→3. You'll be redirected to `/admin` — the dashboard with Overview / Chemicals / SDS tabs.

    68→### 0.4 Why `npm run dev` doesn't work (and how to fix it)
    69→
    70→If you already ran `npm install` and `npm run dev`, you likely hit one of these:
    71→
    72→| Symptom | Cause | Fix |
    73→|---|---|---|
    74→| `npm run dev` fails with `tee: command not found` | Old script used a Unix-only `tee` pipe. **This has been fixed** — update to the latest code, or run `npx next dev -p 3000` directly. | `bun install` (or `npm install`) on latest code, then `bun run dev` |
    75→| `npm run db:seed` fails with `SyntaxError` or `Cannot find module` | The seed script is TypeScript run via Bun. Node/npm can't execute `.ts` files directly. | Install Bun, then run `bun run db:seed` |
    76→| App loads but shows "Database Error" / 0 chemicals | The database hasn't been created/seeded yet. | Run `bun run db:push && bun run db:seed` |
    77→| `PrismaClientInitializationError` | `DATABASE_URL` points to a path that doesn't exist on your machine. | Make sure `.env` has `DATABASE_URL=file:./db/custom.db` (relative path). Run `bun run db:push`. |
    78→| 401 on every admin API | `NEXTAUTH_SECRET` is missing or the `.env` wasn't loaded. | Set `NEXTAUTH_SECRET` in `.env`; restart `bun run dev`. |
    79→| Login fails with "Invalid email or password" | Admin user not created, or `.env` credentials don't match what's in the DB. | Run `bun run db:seed` again (it's idempotent — updates the admin to match `.env`). |
    80→
    81→### 0.5 Migrating from npm to Bun (if you already ran npm install)
    82→
    83→If you already ran `npm install`, you can clean up and switch to Bun:
    84→
    85→```bash
    86→# Remove npm's node_modules and lockfile
    87→rm -rf node_modules package-lock.json
    88→
    89→# Install with Bun
    90→bun install
    91→
    92→# Continue with step 5 onwards (db:push, db:seed, dev)
    93→bun run db:push
    94→bun run db:seed
    95→bun run dev
    96→```
    97→
    98→> **Note:** `bun install` reads the same `package.json` and creates `bun.lockb` instead of `package-lock.json`. Both are fine; just don't mix them.

   135→## 2. High-Level Architecture
   136→
   137→```
   138→┌─────────────────────────────────────────────────────────────────┐
   139→│                        PUBLIC PWA  (/)                          │
   140→│  Catalog → Detail → Emergency views (single-route SPA, Zustand) │
   141→│  Offline-first: all reads go to Dexie (IndexedDB)               │
   142→│  Writes (favorites/notes/prefs) are LOCAL ONLY                  │
   143→└───────────────┬─────────────────────────────────┬───────────────┘
   144→                │ GET /api/sync?since=<ts>         │ GET /api/chemicals
   145→                │ GET /api/sds/[id]/download       │
   146→                ▼                                  ▼
   147→┌─────────────────────────────────────────────────────────────────┐
   148→│                     PUBLIC API (no auth)                        │
   149→│  /api/sync          delta sync (chemicals + SDS metadata)       │
   150→│  /api/chemicals     list / get chemical                         │
   151→│  /api/sds/[id]/download   stream SDS PDF                        │
   152→└───────────────┬─────────────────────────────────────────────────┘
   153→                │ Prisma
   154→                ▼
   155→┌─────────────────────────────────────────────────────────────────┐
   156→│                  PRISMA + SQLite  (source of truth)             │
   157→│  User · Chemical · SdsDocument                                  │
   158→└─────────────────────────────────────────────────────────────────┘
   159→                ▲
   160→                │ requireAdmin()  (server-side session check)
   161→┌───────────────┴─────────────────────────────────────────────────┐
   162→│                    ADMIN API (auth required)                    │
   163→│  /api/admin/dashboard          stats                            │
   164→│  /api/admin/chemicals          POST  (create)                   │
   165→│  /api/admin/chemicals/[id]     GET / PUT / DELETE               │
   166→│  /api/admin/sds                POST  (upload PDF)               │
   167→│  /api/admin/sds/[id]           DELETE (revert to placeholder)   │
   168→└───────────────┬─────────────────────────────────────────────────┘
   169→                ▲
   170→                │ NextAuth session (JWT, httpOnly cookie)
   171→┌───────────────┴─────────────────────────────────────────────────┐
   172→│                    ADMIN UI  (/admin)                           │
   173→│  /admin/login   sign-in form                                    │
   174→│  /admin         dashboard: 6 tabs (last 3 SUPER_ADMIN-only)     │
   175→│  Protected by src/middleware.ts (edge, role=SUPER_ADMIN||ADMIN)   │
   176→└─────────────────────────────────────────────────────────────────┘
   177→```
   178→
   179→### Key principles
   180→- **Server is the source of truth** for chemical & SDS data. Client Dexie DB is a cache.
   181→- **Offline-first:** the public PWA reads from Dexie. It works fully offline after first sync.
   182→- **Delta sync:** clients ask for changes since their last sync timestamp — never the whole DB.
   183→- **SDS PDFs are versioned & cached** as Blobs in IndexedDB; only re-downloaded when version changes.
   184→- **User preferences (favorites/notes) stay local** — never sent to the server, never overwritten.
   185→- **Admin authorization is server-side** in every admin API route (`requireAdmin()`). The edge middleware is defense-in-depth only.

   280→## 4. Database Schema (Prisma)
   281→
   282→### `User` — admin accounts only
   283→| Field | Type | Notes |
   284→|---|---|---|
   285→| id | String (cuid) | PK |
   286→| email | String | unique |
   287→| passwordHash | String | bcrypt (12 rounds) |
   288→| name | String? | optional display name |
   289→| role | String | `"SUPER_ADMIN"` \| `"ADMIN"` \| `"USER"` (only SUPER_ADMIN and ADMIN can sign in; USER is reserved for the public PWA and cannot log in here) |
   290→| disabled | Boolean | default `false` — super-admin can disable an account without deleting it (also blocks sign-in via `authorize()`) |
   291→| passwordChangeRequired | Boolean | default `false` — when `true`, the user is forced to `/admin/change-password` on next login (triple-layered enforcement — see §8) |
   292→| lastLoginAt | DateTime? | updated on each successful sign-in |
   293→| createdAt / updatedAt | DateTime | |
   294→| Relations | `SdsDocument[] uploadedSds`, `Chemical[] updatedChemicals`, `AuditLog[] auditLogs` | audit trail |
   295→
   296→### `Chemical` — central catalog entity
   297→| Field | Type | Notes |
   298→|---|---|---|
   299→| id | String | PK (stable slug, e.g. `chem-acetone`) |
   300→| casNumber, chemicalName, formula | String | identifiers |
   301→| tradeName, manufacturer, supplier | String | provenance |
   302→| signalWord | String | `"danger"` / `"warning"` |
   303→| hazardClasses | String | JSON-encoded `HazardClass[]` |
   304→| ghsPictograms | String | JSON-encoded `GhsPictogram[]` |
   305→| storageLocation, department | String | physical location |
   306→| safetyInstructions | String | |
   307→| version | String | SDS document version label (e.g. `"1.4"`) |
   308→| emergencyContact | String | |
   309→| personalProtectiveEquipment | String | JSON array |
   310→| firstAidMeasures, firefightingMeasures, accidentalReleaseMeasures | String | SDS sections 4/5/6 |
   311→| **serverVersion** | Int | **sync key** — incremented on every update |
   312→| createdAt, updatedAt | DateTime | |
   313→| **deletedAt** | DateTime? | **soft delete** — sync propagates deletes |
   314→| updatedById | String? | FK → User (audit) |
   315→| Relations | `SdsDocument? sdsDocument` | 1:1 |
   316→
   317→Indexes: `updatedAt`, `deletedAt`, `chemicalName`, `casNumber`.
   318→
   319→### `SdsDocument` — one per chemical (1:1)
   320→| Field | Type | Notes |
   321→|---|---|---|
   322→| id | String (cuid) | PK |
   323→| chemicalId | String | unique FK → Chemical (cascade delete) |
   324→| storageKey | String | safe generated filename (`<uuid>.pdf`) — never user-supplied |
   325→| originalFileName | String | for display/download only |
   326→| fileSize, mimeType | Int / String | |
   327→| contentHash | String | sha256 of file content |
   328→| status | String | `"placeholder"` / `"available"` |
   329→| **version** | Int | **incremented on each replace** (client re-download trigger) |
   330→| uploadedById | String? | FK → User (audit) |
   331→| createdAt, updatedAt | DateTime | |
   332→
   333→Indexes: `updatedAt`, `status`.
   334→
   335→### `AuditLog` — append-only trail of every administrative mutation
   336→| Field | Type | Notes |
   337→|---|---|---|
   338→| id | String (cuid) | PK |
   339→| actorId | String? | FK → User, nullable (null for system actions). `onDelete: SetNull` so the log row survives user deletion. |
   340→| actorEmail | String? | Denormalized email — same reason: log survives user deletion. |
   341→| action | String | Dotted convention, e.g. `chemical.create`, `chemical.update`, `chemical.delete`, `sds.upload`, `sds.replace`, `sds.revert`, `user.create`, `user.update`, `user.disable`, `user.delete`, `user.password-change`, `system.test-ai`. |
   342→| entityType | String | `"chemical"` \| `"sds"` \| `"user"` \| `"session"` \| `"system"`. |
   343→| entityId | String | id of the affected entity (or the provider name for `system.*`). |
   344→| summary | String | Human-readable one-liner shown in the audit-log viewer. |
   345→| before | String? | JSON snapshot of state before the mutation (for updates/deletes). |
   346→| after | String? | JSON snapshot of state after the mutation (for creates/updates). |
   347→| ipAddress | String? | Best-effort client IP from `x-forwarded-for` / `x-real-ip`. |
   348→| createdAt | DateTime | default `now()`. |
   349→| Relations | `User? actor` | nullable; `onDelete: SetNull`. |
   350→
   351→Indexes: `createdAt`, `actorId`, `[entityType, entityId]`, `action`.
   352→
   353→Entries are written via `logAction()` in `src/lib/audit.ts` (fire-and-forget — failures are logged to stderr and never propagate to the caller). The viewer (`src/components/admin/audit-log-viewer.tsx`) is cursor-paginated and exposed at `GET /api/admin/audit` (SUPER_ADMIN only).

   357→## 5. Client Database (Dexie v2)
   358→
   359→```
   360→chemicals      : ChemicalRecord  (keyPath: id)        + indexes on casNumber, department, etc.
   361→sdsDocuments   : SdsMeta          (keyPath: chemicalId)
   362→sdsBlobs       : { chemicalId, version, blob, fetchedAt }   ← SDS PDF Blob cache
   363→syncMeta       : { key, value }   ← lastSyncTimestamp, syncMutex, etc.
   364→locations      : LaboratoryLocation
   365→preferences    : UserPreferences  (favorites, notes, theme — LOCAL ONLY)
   366→```
   367→
   368→**Why two stores?** `sdsDocuments` holds metadata (small, synced as JSON). `sdsBlobs` holds the actual PDF Blob (large, only re-fetched when `version` changes).

   372→## 6. API Reference
   373→
   374→### Public (no auth)
   375→| Method | Path | Purpose |
   376→|---|---|---|
   377→| GET | `/api/sync?since=<epoch-ms>` | Delta sync. Returns `{ chemicals: [...], sdsDocuments: [...], deletedChemicalIds: [...], serverTime }`. Only records with `updatedAt > since` (or `deletedAt > since`) are returned. |
   378→| GET | `/api/chemicals` | List all non-deleted chemicals (metadata only, no PDF). |
   379→| GET | `/api/chemicals/[id]` | Single chemical. |
   380→| GET | `/api/sds/[id]/download` | Stream the SDS PDF for chemical `[id]`. Sets `Content-Type: application/pdf`. Used by both the public PWA (caches Blob) and admin "View". |
   381→
   382→### Admin (auth required — `requireAdmin()`)
   383→| Method | Path | Purpose |
   384→|---|---|---|
   385→| GET | `/api/admin/dashboard` | Stats: total chemicals, SDS coverage, department distribution, recent updates. |
   386→| POST | `/api/admin/chemicals` | Create chemical. Auto-creates a placeholder `SdsDocument`. Body validated by zod. |
   387→| GET | `/api/admin/chemicals/[id]` | Read single (admin view). |
   388→| PUT | `/api/admin/chemicals/[id]` | Update. Bumps `serverVersion`. Sets `updatedById`. |
   389→| DELETE | `/api/admin/chemicals/[id]` | Soft-delete (`deletedAt = now`). Cascade-soft-deletes the SDS. |
   390→| POST | `/api/admin/sds` | Upload / replace SDS PDF. Multipart form. Validates magic bytes + MIME + extension + size. Stores with UUID filename. Increments `version`, sets `status = available`. |
   391→| DELETE | `/api/admin/sds/[id]` | Revert to placeholder. Removes the uploaded file, resets `status = placeholder`, increments `version`. |
   392→| POST | `/api/admin/sds/extract` | **AI auto-fill.** Accepts an SDS PDF (multipart), rasterizes first 5 pages to PNG, sends to the configured VLM provider (`src/lib/ai-vlm.ts`), parses + sanitizes the JSON response, returns `{ success, data }`. 60s timeout. See §6A. |
   393→
   394→### Super-admin only (`requireSuperAdmin()`)
   395→| Method | Path | Purpose |
   396→|---|---|---|
   397→| GET | `/api/admin/users` | List all admin accounts (SUPER_ADMIN + ADMIN). `passwordHash` is never included in the response. |
   398→| POST | `/api/admin/users` | Create admin. Zod-validated body: `email`, `password` (≥8 chars), `name?`, `role` (`ADMIN` \\| `SUPER_ADMIN`, default `ADMIN`), `passwordChangeRequired` (default `true`). Returns 409 on duplicate email. Audit-logs `user.create`. |
   399→| PATCH | `/api/admin/users/[id]` | Update `name` / `role` / `disabled` / `password` / `passwordChangeRequired`. At least one field required. **Lockout guards**: cannot change own role away from `SUPER_ADMIN`; cannot disable self; cannot disable / downgrade / delete the last active super-admin. Resetting a password implicitly sets `passwordChangeRequired=true` unless the same PATCH explicitly sets it to `false`. Audit-logs `user.update` (or `user.disable` when `disabled: true` is set). |
   400→| DELETE | `/api/admin/users/[id]` | Permanently delete admin. Same lockout guards as PATCH (cannot delete self; cannot delete last active super-admin). Audit-logs `user.delete`. |
   401→| GET | `/api/admin/audit?cursor=&limit=&entityType=&action=&actorId=` | Cursor-paginated audit log (newest first). Defaults: `limit=50`, max `100`. `cursor` is the ISO timestamp of the last row on the previous page. Fetches `limit+1` rows to detect `hasMore`; returns `{ entries, nextCursor, hasMore }`. Filters are all optional: `entityType`, `action` (matched as a **prefix** — e.g. `action=user.`), `actorId`. |
   402→| GET | `/api/admin/system/info` | Returns 5 read-only info blocks: **ai** (provider config from `getProviderInfo()` — masked key, never the actual key), **storage** (walks `storage/sds/` for totalBytes / fileCount / largestFile / averageBytes), **database** (SQLite file size + path + `DATABASE_URL`), **sync** (chemical/SDS/user/auditLog counts + `lastUpdatedAt` + `maxServerVersion` — 7 parallel DB queries), **system** (`nodeVersion`, `platform`, `arch`, `environment`, `nextjsVersion`, `uptimeSeconds`, `currentTime`, `timezone`). |
   403→| POST | `/api/admin/system/test-ai` | Calls `testProviderConnection()` — sends a minimal text-only prompt (`'Reply with exactly the JSON: {"ok":true}'`) to the configured VLM provider. Returns `{ ok, provider, model, latencyMs, responsePreview, error? }`. **Never sends an image, never touches the DB.** Audit-logs as `system.test-ai` with the result + latency in the `after` snapshot. |
   404→
   405→### Any authenticated admin (used by the password-change flow)
   406→| Method | Path | Purpose |
   407→|---|---|---|
   408→| POST | `/api/admin/change-password` | Body: `{ currentPassword, newPassword }`. Verifies `currentPassword` against the user's bcrypt hash, rejects if `newPassword === currentPassword`, hashes the new password, updates the DB (`passwordHash` + `passwordChangeRequired=false`), audit-logs `user.password-change`. **Uses `getServerSession` directly (NOT `requireAdmin()`)** so that users with `passwordChangeRequired === true` can still call it — this is the one API route that bypasses the password-change gate. |

   413→| POST | `/api/auth/callback/credentials` | NextAuth credentials sign-in. |

   418→## 6A. AI Auto-Fill Architecture (VLM Provider Abstraction)
   419→
   420→The "Auto-fill from PDF" feature reads an uploaded SDS PDF using a vision-language
   421→model (VLM) and returns structured JSON fields. The provider is swappable via the
   422→`AI_PROVIDER` env var so the same code works on the sandbox (free in-house AI) and
   423→on a local machine (free Google Gemini tier).
   424→
   425→### Request flow
   426→
   427→```
   428→Admin UI (chemical-manager.tsx)
   429→  └─ user clicks "Auto-fill from PDF", selects a .pdf file
   430→  └─ POST /api/admin/sds/extract  (multipart: file=...)
   431→       │
   432→       ├─ requireAdmin()                          ← server-side authz
   433→       ├─ validate file (magic bytes %PDF- + MIME + .pdf + size)
   434→       ├─ assertProviderConfigured(provider)      ← fail fast if key missing
   435→       ├─ rasterizePdfToPngs(buffer, {maxPages:5, scale:2})   ← src/lib/pdf-rasterize.ts
   436→       │     └─ pdfjs-dist + @napi-rs/canvas (pure JS, no Poppler)
   437→       ├─ callVlm(pageImages, EXTRACTION_PROMPT)  ← src/lib/ai-vlm.ts
   438→       │     ├─ AI_PROVIDER=zai       → z-ai-web-dev-sdk (glm-4.6v)   [sandbox default]
   439→       │     ├─ AI_PROVIDER=gemini    → @google/generative-ai (gemini-3.6-flash)
   440→       │     ├─ AI_PROVIDER=openai    → openai SDK (gpt-4o-mini)
   441→       │     └─ AI_PROVIDER=anthropic → @anthropic-ai/sdk (claude-3-5-sonnet)
   442→       ├─ extractJson(rawResponse)                 ← strip markdown fences
   443→       ├─ JSON.parse + sanitize (enum filter, trim, dedupe)
   444→       └─ return { success: true, data: {…15 fields…} }
   445→  └─ frontend merges fields into the chemical form (preserves the manual `id` field)

   512→## 7. Sync Engine (`src/lib/sync-engine.ts`)
   513→
   514→### Trigger points
   515→1. **App startup** — fires once Dexie is initialized.
   516→2. **Offline → online transition** — `use-online-status` hook notifies the engine.
   517→3. **Periodic** — runs every few minutes while online.
   518→
   519→### Algorithm
   520→```
   521→1. Acquire mutex (in Dexie.syncMeta) — prevents concurrent syncs across tabs.
   522→2. Read lastSyncTimestamp from syncMeta.
   523→3. GET /api/sync?since=<lastSyncTimestamp>.
   524→4. For each chemical in response:
   525→   - If deleted (deletedAt > since) → remove from Dexie.chemicals.
   526→   - Else → upsert into Dexie.chemicals.
   527→5. For each sdsDocument in response:
   528→   - Upsert metadata into Dexie.sdsDocuments.
   529→   - Compare version with Dexie.sdsBlobs.
   530→     - If version unchanged AND blob exists → skip (no re-download).
   531→     - If version changed OR blob missing → GET /api/sds/[id]/download,
   532→       store Blob in Dexie.sdsBlobs with new version.
   533→6. Persist new lastSyncTimestamp = response.serverTime.
   534→7. Release mutex. Update Zustand sync status.
   535→```
   536→
   537→### Rate limiting
   538→A minimum interval between sync attempts prevents hammering the server on flaky connections. Manual retry from the UI bypasses the interval once.
   539→
   540→### Status states (the `SyncStatus` type)
   541→| State | Meaning |
   542→|---|---|
   543→| `offline` | Navigator reports offline. No sync attempts. |
   544→| `syncing` | A sync is in progress. |
   545→| `synced` | Last sync completed successfully and we're online. |
   546→| `local-changes` | *(reserved)* user has local-only changes that couldn't be pushed (currently preferences only — always local). |
   547→| `error` | Last sync attempt failed. UI shows a retry button. |
   548→
   549→### Conflict resolution
   550→- **Chemical / SDS data:** server-wins. The latest `updatedAt` always wins.
   551→- **User preferences / favorites / notes:** local-only, never synced, never overwritten.

   555→## 8. Security Model
   556→
   557→### Authentication
   558→- NextAuth Credentials provider.
   559→- **3-tier role hierarchy**: `SUPER_ADMIN` > `ADMIN` > `USER`. Only `SUPER_ADMIN` and `ADMIN` can sign in to `/admin/*`; `USER` is reserved for the public PWA and is rejected by `authorize()`.
   560→- Disabled accounts (`disabled === true`) cannot sign in.
   561→- Passwords hashed with **bcrypt (12 rounds)** — never stored or logged in plaintext.
   562→- JWT session strategy, 30-day max age. The JWT carries `id`, `role`, and `passwordChangeRequired`; the `session` callback copies them onto `session.user`.
   563→- On `useSession().update()` (trigger `"update"`), the `jwt` callback re-fetches `passwordChangeRequired` + `role` from the DB so a just-completed password change is reflected without a fresh sign-in.
   564→- Cookies: `httpOnly`, `sameSite=lax`, `secure` in production (`__Secure-` prefix).
   565→
   566→### Authorization (defense in depth)
   567→1. **Edge middleware** (`src/middleware.ts`) — blocks `/admin/*` (except `/admin/login`) unless the JWT has `role === "SUPER_ADMIN" || role === "ADMIN"`. Fast, runs at the edge. (Super-admin-only routes enforce the stricter check server-side via `requireSuperAdmin()`.)
   568→2. **`requireAdmin()`** (in `src/lib/session.ts`) — every admin API route for chemicals / SDS / dashboard / change-password-adjacent features calls this. Returns 401 if the session is missing or the user is not `ADMIN` / `SUPER_ADMIN`. **Also returns 401 if the user has `passwordChangeRequired === true`** — defense-in-depth so a bypassed client guard still can't reach the API.
   569→3. **`requireSuperAdmin()`** (in `src/lib/session.ts`) — same shape as `requireAdmin()` but additionally requires `role === "SUPER_ADMIN"`. Used by user-management, audit-log, and system-settings routes. Also blocks `passwordChangeRequired` users.
   570→4. **`PasswordGuard`** client component (`src/components/admin/password-guard.tsx`) — mounted in the admin layout. Uses `useSession()` + `usePathname()`; if the current path is NOT `/admin/login` and NOT `/admin/change-password`, and the session has `passwordChangeRequired === true`, hard-redirects to `/admin/change-password`.
   571→
   572→### Audit log
   573→Every chemical / SDS / user / system mutation is logged via `logAction()` in `src/lib/audit.ts`.
   574→- **Fire-and-forget**: `logAction()` wraps its `db.auditLog.create()` in a `try/catch` and only logs to `stderr` on failure. An audit-log problem can **never** break the main operation the user is trying to perform.
   575→- **Captures**: `actorId`, `actorEmail` (denormalized so the row survives user deletion), `action` (dotted, e.g. `chemical.create`, `user.disable`, `system.test-ai`), `entityType`, `entityId`, `summary`, `before` / `after` JSON snapshots (built via `snapshotChemical()` for chemicals), and a best-effort `ipAddress` (from `x-forwarded-for` / `x-real-ip` via `auditContext()`).
   576→- **Storage**: `AuditLog` table (append-only — no update / delete endpoints exist). Indexed on `createdAt`, `actorId`, `[entityType, entityId]`, `action`.
   577→- **Viewer**: `GET /api/admin/audit` (SUPER_ADMIN only), cursor-paginated. UI: `src/components/admin/audit-log-viewer.tsx`.
   578→
   579→### Password change enforcement (triple-layered)
   580→When a super-admin creates a user with a temporary password (or resets an existing user's password), `passwordChangeRequired` is set to `true`. The user is then forced to change their password on next login via three independent layers:
   581→1. **Client-side guard** — `PasswordGuard` (`src/components/admin/password-guard.tsx`) redirects to `/admin/change-password` as soon as the session loads. Bypassing this is possible (disable JS), so it's UX + first line of defense only.
   582→2. **Server-side guard** — both `requireAdmin()` and `requireSuperAdmin()` return 401 when `passwordChangeRequired === true`. So a user with the flag set cannot call any admin API route except the change-password endpoint.
   583→3. **Verified current password** — `POST /api/admin/change-password` calls `getServerSession` directly (NOT `requireAdmin()`), verifies `currentPassword` against the bcrypt hash, rejects if `newPassword === currentPassword`, hashes the new password, sets `passwordChangeRequired=false`, and audit-logs `user.password-change`. The client then calls `useSession().update()` so the JWT refreshes without a fresh sign-in.
   584→
   585→The change-password route is the **only** admin API route that does not go through `requireAdmin()` / `requireSuperAdmin()` — by design, so the flag-bearer can still escape the gate.
   586→
   587→### SDS file upload safety
   588→- **Magic-byte validation** — the file must start with `%PDF-` (PDF signature). Renamed non-PDFs are rejected.
   589→- **MIME type check** — must be `application/pdf`.
   590→- **Extension check** — must end in `.pdf`.
   591→- **Size limit** — enforced (see `validation.ts`).
   592→- **Filename handling** — user-supplied filename is stored only for display/download. The actual stored file is named `<uuid>.pdf` under `storage/`. No path traversal possible.
   593→- **No path exposure** — `storageKey` is a UUID, never the original path.
   594→
   595→### Input validation
   596→- All admin chemical inputs validated with **zod** schemas before reaching Prisma.
   597→- Prisma parameterizes all queries — no raw SQL, no SQL injection surface.
   598→
   599→### Security headers (`next.config.ts`)
   600→- Content-Security-Policy
   601→- X-Frame-Options: DENY
   602→- X-Content-Type-Options: nosniff
   603→- Referrer-Policy
   604→- Strict-Transport-Security (HSTS)
   605→- Permissions-Policy
   606→
   607→### Secrets
   608→- `NEXTAUTH_SECRET` — required in production. Generate with:
   609→  ```bash
   610→  bun -e 'console.log(require("crypto").randomBytes(32).toString("hex"))'
   611→  ```
   612→- `ADMIN_PASSWORD` — plaintext in `.env` only; hashed before DB storage.
   613→- `.env` is gitignored. `.env.example` is the committed template.
   614→
   615→### Known platform-level caveat
   616→The sandbox gateway (`Caddyfile`) uses an `XTransformPort` query param for port routing. This is an open-proxy-style SSRF surface at the **infra level** and is outside the application code. Flag for the platform team before any public deployment.

   745→5. Add role-based checks (or zod enum extensions for `role` in `createUserSchema` / `updateUserSchema`) in the relevant API routes. The user-manager UI (`src/components/admin/user-manager.tsx`) also has a hard-coded role Select that may need the new option.

   756→| `PrismaClientInitializationError` | DB file missing or path wrong | Check `DATABASE_URL` in `.env`; run `bun run db:push` |
   757→| `bun run db:seed` does nothing | Admin already exists with same email | It's idempotent — it upserts. Check `SELECT * FROM User`. |
   758→| 401 on every admin API even when "logged in" | Session cookie not sent (cross-origin / different port) | Ensure requests use relative paths; in this sandbox use `XTransformPort` for cross-service calls |
   759→| SDS upload 413 | File too large | Check the size limit in `src/lib/validation.ts` / reverse proxy |
   760→| Dexie schema version conflict | Old client DB version | Bump Dexie schema version in `src/lib/local-db.ts` with an upgrade function |
   761→| Service worker not updating | Old SW cached | Bump `CACHE_VERSION` in `public/sw.js`; user will get new SW on next load |
   762→| Preview shows blank "Z" screen | Dev server not running | `bun run dev` (this is the most common "it's loading" report) |
