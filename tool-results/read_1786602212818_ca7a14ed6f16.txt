    23→    23→### 0.2 Step-by-Step (fresh clone)
    24→    24→
    25→    25→```bash
    26→    26→# 1. Clone the repository
    27→    27→git clone <your-repo-url> sds-chem
    28→    28→cd sds-chem
    29→    29→
    30→    30→# 2. Install dependencies with Bun (do NOT use npm install)
    31→    31→bun install
    32→    32→
    33→    33→# 3. Create your environment file from the template
    34→    34→cp .env.example .env
    35→    35→
    36→    36→# 4. Edit .env — set these values:
    37→    37→#    - ADMIN_EMAIL         (your admin login email)
    38→    38→#    - ADMIN_PASSWORD      (a strong password — will be bcrypt-hashed)
    39→    39→#    - NEXTAUTH_SECRET     (generate one — see the comment in .env.example)
    40→    40→#    - DATABASE_URL        (already set to ./db/custom.db — leave as-is)
    41→    41→#    - NEXTAUTH_URL        (already http://localhost:3000 — leave as-is)
    42→    42→#
    43→    43→#    Generate a NEXTAUTH_SECRET with:
    44→    44→#      bun -e 'console.log(require("crypto").randomBytes(32).toString("hex"))'
    45→    45→#      node -e "console.log(require('crypto').randomBytes(32).toString('hex'))'"
    46→    46→
    47→    47→# 5. Create the SQLite database + tables
    48→    48→bun run db:push
    49→    49→
    50→    50→# 6. Seed the database:
    51→    51→#    - Creates the admin user from ADMIN_EMAIL / ADMIN_PASSWORD
    52→    52→#    - Imports the 14 seed chemicals
    53→    53→#    - Generates a placeholder SDS PDF for each chemical
    54→    54→bun run db:seed
    55→    55→
    56→    56→# 7. Start the dev server
    57→    57→bun run dev
    58→    58→```
    59→    59→
    60→    60→Open **http://localhost:3000** in your browser. You should see the chemical catalog with 14 chemicals.

    68→    68→### 0.4 Why `npm run dev` doesn't work (and how to fix it)
    69→    69→
    70→    70→If you already ran `npm install` and `npm run dev`, you likely hit one of these:
    71→    71→
    72→    72→| Symptom | Cause | Fix |
    73→    73→|---|---|---|
    74→    74→| `npm run dev` fails with `tee: command not found` | Old script used a Unix-only `tee` pipe. **This has been fixed** — update to the latest code, or run `npx next dev -p 3000` directly. | `bun install` (or `npm install`) on latest code, then `bun run dev` |
    75→    75→| `npm run db:seed` fails with `SyntaxError` or `Cannot find module` | The seed script is TypeScript run via Bun. Node/npm can't execute `.ts` files directly. | Install Bun, then run `bun run db:seed` |
    76→    76→| App loads but shows "Database Error" / 0 chemicals | The database hasn't been created/seeded yet. | Run `bun run db:push && bun run db:seed` |
    77→    77→| `PrismaClientInitializationError` | `DATABASE_URL` points to a path that doesn't exist on your machine. | Make sure `.env` has `DATABASE_URL=file:./db/custom.db` (relative path). Run `bun run db:push`. |
    78→    78→| 401 on every admin API | `NEXTAUTH_SECRET` is missing or the `.env` wasn't loaded. | Set `NEXTAUTH_SECRET` in `.env`; restart `bun run dev`. |
    79→    79→| Login fails with "Invalid email or password" | Admin user not created, or `.env` credentials don't match what's in the DB. | Run `bun run db:seed` again (it's idempotent — updates the admin to match `.env`). |

   135→   135→## 2. High-Level Architecture
   136→   136→
   137→   137→```
   138→   138→┌─────────────────────────────────────────────────────────────────┐
   139→   139→│                        PUBLIC PWA  (/)                          │
   140→   140→│  Catalog → Detail → Emergency views (single-route SPA, Zustand) │
   141→   141→│  Offline-first: all reads go to Dexie (IndexedDB)               │
   142→   142→│  Writes (favorites/notes/prefs) are LOCAL ONLY                  │
   143→   143→└───────────────┬─────────────────────────────────┬───────────────┘
   144→   144→                │ GET /api/sync?since=<ts>         │ GET /api/chemicals
   145→   145→                │ GET /api/sds/[id]/download       │
   146→   146→                ▼                                  ▼
   147→   147→┌─────────────────────────────────────────────────────────────────┐
   148→   148→│                     PUBLIC API (no auth)                        │
   149→   149→│  /api/sync          delta sync (chemicals + SDS metadata)       │
   150→   150→│  /api/chemicals     list / get chemical                         │
   151→   151→│  /api/sds/[id]/download   stream SDS PDF                        │
   152→   152→└───────────────┬─────────────────────────────────────────────────┘
   153→   153→                │ Prisma
   154→   154→                ▼
   155→   155→┌─────────────────────────────────────────────────────────────────┐
   156→   156→│                  PRISMA + SQLite  (source of truth)             │
   157→   157→│  User · Chemical · SdsDocument                                  │
   158→   158→└─────────────────────────────────────────────────────────────────┘
   159→   159→                ▲
   160→   160→                │ requireAdmin()  (server-side session check)
   161→   161→┌───────────────┴─────────────────────────────────────────────────┐
   162→   162→│                    ADMIN API (auth required)                    │
   163→   163→│  /api/admin/dashboard          stats                            │
   164→   164→│  /api/admin/chemicals          POST  (create)                   │
   165→   165→│  /api/admin/chemicals/[id]     GET / PUT / DELETE               │
   166→   166→│  /api/admin/sds                POST  (upload PDF)               │
   167→   167→│  /api/admin/sds/[id]           DELETE (revert to placeholder)   │
   168→   168→└───────────────┬─────────────────────────────────────────────────┘
   169→   169→                ▲
   170→   170→                │ NextAuth session (JWT, httpOnly cookie)
   171→   171→┌───────────────┴─────────────────────────────────────────────────┐
   172→   172→│                    ADMIN UI  (/admin)                           │
   173→   173→│  /admin/login   sign-in form                                    │
   174→   174→│  /admin         dashboard: Overview / Chemicals / SDS tabs      │
   175→   175→│  Protected by src/middleware.ts (edge, role=ADMIN)              │
   176→   176→└─────────────────────────────────────────────────────────────────┘
   177→   177→```
   178→   178→
   179→   179→### Key principles
   180→   180→- **Server is the source of truth** for chemical & SDS data. Client Dexie DB is a cache.
   181→   181→- **Offline-first:** the public PWA reads from Dexie. It works fully offline after first sync.
   182→   182→- **Delta sync:** clients ask for changes since their last sync timestamp — never the whole DB.
   183→   183→- **SDS PDFs are versioned & cached** as Blobs in IndexedDB; only re-downloaded when version changes.
   184→   184→- **User preferences (favorites/notes) stay local** — never sent to the server, never overwritten.
   185→   185→- **Admin authorization is server-side** in every admin API route (`requireAdmin()`). The edge middleware is defense-in-depth only.

   278→   278→## 4. Database Schema (Prisma)
   279→   279→
   280→   280→### `User` — admin accounts only
   281→   281→| Field | Type | Notes |
   282→   282→|---|---|---|
   283→   283→| id | String (cuid) | PK |
   284→   284→| email | String | unique |
   285→   285→| passwordHash | String | bcrypt (12 rounds) |
   286→   286→| name | String? | optional display name |
   287→   287→| role | String | `"ADMIN"` or `"USER"` (only ADMIN can log in) |
   288→   288→| createdAt / updatedAt | DateTime | |
   289→   289→| Relations | `SdsDocument[] uploadedSds`, `Chemical[] updatedChemicals` | audit trail |
   290→   290→
   291→   291→### `Chemical` — central catalog entity
   292→   292→| Field | Type | Notes |
   293→   293→|---|---|---|
   294→   294→| id | String | PK (stable slug, e.g. `chem-acetone`) |
   295→   295→| casNumber, chemicalName, formula | String | identifiers |
   296→   296→| tradeName, manufacturer, supplier | String | provenance |
   297→   297→| signalWord | String | `"danger"` / `"warning"` |
   298→   298→| hazardClasses | String | JSON-encoded `HazardClass[]` |
   299→   299→| ghsPictograms | String | JSON-encoded `GhsPictogram[]` |
   300→   300→| storageLocation, department | String | physical location |
   301→   301→| safetyInstructions | String | |
   302→   302→| version | String | SDS document version label (e.g. `"1.4"`) |
   303→   303→| emergencyContact | String | |
   304→   304→| personalProtectiveEquipment | String | JSON array |
   305→   305→| firstAidMeasures, firefightingMeasures, accidentalReleaseMeasures | String | SDS sections 4/5/6 |
   306→   306→| **serverVersion** | Int | **sync key** — incremented on every update |
   307→   307→| createdAt, updatedAt | DateTime | |
   308→   308→| **deletedAt** | DateTime? | **soft delete** — sync propagates deletes |
   309→   309→| updatedById | String? | FK → User (audit) |
   310→   310→| Relations | `SdsDocument? sdsDocument` | 1:1 |
   311→   311→
   312→   312→Indexes: `updatedAt`, `deletedAt`, `chemicalName`, `casNumber`.
   313→   313→
   314→   314→### `SdsDocument` — one per chemical (1:1)
   315→   315→| Field | Type | Notes |
   316→   316→|---|---|---|
   317→   317→| id | String (cuid) | PK |
   318→   318→| chemicalId | String | unique FK → Chemical (cascade delete) |
   319→   319→| storageKey | String | safe generated filename (`<uuid>.pdf`) — never user-supplied |
   320→   320→| originalFileName | String | for display/download only |
   321→   321→| fileSize, mimeType | Int / String | |
   322→   322→| contentHash | String | sha256 of file content |
   323→   323→| status | String | `"placeholder"` / `"available"` |
   324→   324→| **version** | Int | **incremented on each replace** (client re-download trigger) |
   325→   325→| uploadedById | String? | FK → User (audit) |
   326→   326→| createdAt, updatedAt | DateTime | |
   327→   327→
   328→   328→Indexes: `updatedAt`, `status`.

   332→   332→## 5. Client Database (Dexie v2)
   333→   333→
   334→   334→```
   335→   335→chemicals      : ChemicalRecord  (keyPath: id)        + indexes on casNumber, department, etc.
   336→   336→sdsDocuments   : SdsMeta          (keyPath: chemicalId)
   337→   337→sdsBlobs       : { chemicalId, version, blob, fetchedAt }   ← SDS PDF Blob cache
   338→   338→syncMeta       : { key, value }   ← lastSyncTimestamp, syncMutex, etc.
   339→   339→locations      : LaboratoryLocation
   340→   340→preferences    : UserPreferences  (favorites, notes, theme — LOCAL ONLY)
   341→   341→```
   342→   342→
   343→   343→**Why two stores?** `sdsDocuments` holds metadata (small, synced as JSON). `sdsBlobs` holds the actual PDF Blob (large, only re-fetched when `version` changes).

   347→   347→## 6. API Reference
   348→   348→
   349→   349→### Public (no auth)
   350→   350→| Method | Path | Purpose |
   351→   351→|---|---|---|
   352→   352→| GET | `/api/sync?since=<epoch-ms>` | Delta sync. Returns `{ chemicals: [...], sdsDocuments: [...], deletedChemicalIds: [...], serverTime }`. Only records with `updatedAt > since` (or `deletedAt > since`) are returned. |
   353→   353→| GET | `/api/chemicals` | List all non-deleted chemicals (metadata only, no PDF). |
   354→   354→| GET | `/api/chemicals/[id]` | Single chemical. |
   355→   355→| GET | `/api/sds/[id]/download` | Stream the SDS PDF for chemical `[id]`. Sets `Content-Type: application/pdf`. Used by both the public PWA (caches Blob) and admin "View". |
   356→   356→
   357→   357→### Admin (auth required — `requireAdmin()`)
   358→   358→| Method | Path | Purpose |
   359→   359→|---|---|---|
   360→   360→| GET | `/api/admin/dashboard` | Stats: total chemicals, SDS coverage, department distribution, recent updates. |
   361→   361→| POST | `/api/admin/chemicals` | Create chemical. Auto-creates a placeholder `SdsDocument`. Body validated by zod. |
   362→   362→| GET | `/api/admin/chemicals/[id]` | Read single (admin view). |
   363→   363→| PUT | `/api/admin/chemicals/[id]` | Update. Bumps `serverVersion`. Sets `updatedById`. |
   364→   364→| DELETE | `/api/admin/chemicals/[id]` | Soft-delete (`deletedAt = now`). Cascade-soft-deletes the SDS. |
   365→   365→| POST | `/api/admin/sds` | Upload / replace SDS PDF. Multipart form. Validates magic bytes + MIME + extension + size. Stores with UUID filename. Increments `version`, sets `status = available`. |
   366→   366→| DELETE | `/api/admin/sds/[id]` | Revert to placeholder. Removes the uploaded file, resets `status = placeholder`, increments `version`. |
   367→   367→| POST | `/api/admin/sds/extract` | **AI auto-fill.** Accepts an SDS PDF (multipart), rasterizes first 5 pages to PNG, sends to the configured VLM provider (`src/lib/ai-vlm.ts`), parses + sanitizes the JSON response, returns `{ success, data }`. 60s timeout. See §6A. |
   368→   368→
   369→   369→### Auth
   370→   370→| Method | Path | Purpose |
   371→   371→|---|---|---|
   372→   372→| POST | `/api/auth/callback/credentials` | NextAuth credentials sign-in. |
   373→   373→| GET/POST | `/api/auth/*` | NextAuth session / csrf / signout handlers. |

   377→   377→## 6A. AI Auto-Fill Architecture (VLM Provider Abstraction)
   378→   378→
   379→   379→The "Auto-fill from PDF" feature reads an uploaded SDS PDF using a vision-language
   380→   380→model (VLM) and returns structured JSON fields. The provider is swappable via the
   381→   381→`AI_PROVIDER` env var so the same code works on the sandbox (free in-house AI) and
   382→   382→on a local machine (free Google Gemini tier).
   383→   383→
   384→   384→### Request flow
   385→   385→
   386→   386→```
   387→   387→Admin UI (chemical-manager.tsx)
   388→   388→  └─ user clicks "Auto-fill from PDF", selects a .pdf file
   389→   389→  └─ POST /api/admin/sds/extract  (multipart: file=...)
   390→   390→       │
   391→   391→       ├─ requireAdmin()                          ← server-side authz
   392→   392→       ├─ validate file (magic bytes %PDF- + MIME + .pdf + size)
   393→   393→       ├─ assertProviderConfigured(provider)      ← fail fast if key missing
   394→   394→       ├─ rasterizePdfToPngs(buffer, {maxPages:5, scale:2})   ← src/lib/pdf-rasterize.ts
   395→   395→       │     └─ pdfjs-dist + @napi-rs/canvas (pure JS, no Poppler)
   396→   396→       ├─ callVlm(pageImages, EXTRACTION_PROMPT)  ← src/lib/ai-vlm.ts
   397→   397→       │     ├─ AI_PROVIDER=zai       → z-ai-web-dev-sdk (glm-4.6v)   [sandbox default]
   398→   398→       │     ├─ AI_PROVIDER=gemini    → @google/generative-ai (gemini-3.6-flash)
   399→   399→       │     ├─ AI_PROVIDER=openai    → openai SDK (gpt-4o-mini)
   400→   400→       │     └─ AI_PROVIDER=anthropic → @anthropic-ai/sdk (claude-3-5-sonnet)
   401→   401→       ├─ extractJson(rawResponse)                 ← strip markdown fences
   402→   402→       ├─ JSON.parse + sanitize (enum filter, trim, dedupe)
   403→   403→       └─ return { success: true, data: {…15 fields…} }
   404→   404→  └─ frontend merges fields into the chemical form (preserves the manual `id` field)
   405→   405→```

   471→   471→## 7. Sync Engine (`src/lib/sync-engine.ts`)
   472→   472→
   473→   473→### Trigger points
   474→   474→1. **App startup** — fires once Dexie is initialized.
   475→   475→2. **Offline → online transition** — `use-online-status` hook notifies the engine.
   476→   476→3. **Periodic** — runs every few minutes while online.
   477→   477→
   478→   478→### Algorithm
   479→   479→```
   480→   480→1. Acquire mutex (in Dexie.syncMeta) — prevents concurrent syncs across tabs.
   481→   481→2. Read lastSyncTimestamp from syncMeta.
   482→   482→3. GET /api/sync?since=<lastSyncTimestamp>.
   483→   483→4. For each chemical in response:
   484→   484→   - If deleted (deletedAt > since) → remove from Dexie.chemicals.
   485→   485→   - Else → upsert into Dexie.chemicals.
   486→   486→5. For each sdsDocument in response:
   487→   487→   - Upsert metadata into Dexie.sdsDocuments.
   488→   488→   - Compare version with Dexie.sdsBlobs.
   489→   489→     - If version unchanged AND blob exists → skip (no re-download).
   490→   490→     - If version changed OR blob missing → GET /api/sds/[id]/download,
   491→   491→       store Blob in Dexie.sdsBlobs with new version.
   492→   492→6. Persist new lastSyncTimestamp = response.serverTime.
   493→   493→7. Release mutex. Update Zustand sync status.
   494→   494→```
   495→   495→
   496→   496→### Rate limiting
   497→   497→A minimum interval between sync attempts prevents hammering the server on flaky connections. Manual retry from the UI bypasses the interval once.
   498→   498→
   499→   499→### Status states (the `SyncStatus` type)
   500→   500→| State | Meaning |
   501→   501→|---|---|
   502→   502→| `offline` | Navigator reports offline. No sync attempts. |
   503→   503→| `syncing` | A sync is in progress. |
   504→   504→| `synced` | Last sync completed successfully and we're online. |
   505→   505→| `local-changes` | *(reserved)* user has local-only changes that couldn't be pushed (currently preferences only — always local). |
   506→   506→| `error` | Last sync attempt failed. UI shows a retry button. |
   507→   507→
   508→   508→### Conflict resolution
   509→   509→- **Chemical / SDS data:** server-wins. The latest `updatedAt` always wins.
   510→   510→- **User preferences / favorites / notes:** local-only, never synced, never overwritten.

   514→   514→## 8. Security Model
   515→   515→
   516→   516→### Authentication
   517→   517→- NextAuth Credentials provider.
   518→   518→- Passwords hashed with **bcrypt (12 rounds)** — never stored or logged in plaintext.
   519→   519→- JWT session strategy, 30-day max age.
   520→   520→- Cookies: `httpOnly`, `sameSite=lax`, `secure` in production (`__Secure-` prefix).
   521→   521→
   522→   522→### Authorization (defense in depth)
   523→   523→1. **Edge middleware** (`src/middleware.ts`) — blocks `/admin/*` (except `/admin/login`) unless the JWT has `role === "ADMIN"`. Fast, runs at the edge.
   524→   524→2. **Server-side guard** (`requireAdmin()` in `src/lib/session.ts`) — every admin API route calls this. Returns 401 if no valid admin session. This is the real enforcement layer; the middleware is just a UX optimization / defense-in-depth.
   525→   525→
   526→   526→### SDS file upload safety
   527→   527→- **Magic-byte validation** — the file must start with `%PDF-` (PDF signature). Renamed non-PDFs are rejected.
   528→   528→- **MIME type check** — must be `application/pdf`.
   529→   529→- **Extension check** — must end in `.pdf`.
   530→   530→- **Size limit** — enforced (see `validation.ts`).
   531→   531→- **Filename handling** — user-supplied filename is stored only for display/download. The actual stored file is named `<uuid>.pdf` under `storage/`. No path traversal possible.
   532→   532→- **No path exposure** — `storageKey` is a UUID, never the original path.
   533→   533→
   534→   534→### Input validation
   535→   535→- All admin chemical inputs validated with **zod** schemas before reaching Prisma.
   536→   536→- Prisma parameterizes all queries — no raw SQL, no SQL injection surface.
   537→   537→
   538→   538→### Security headers (`next.config.ts`)
   539→   539→- Content-Security-Policy
   540→   540→- X-Frame-Options: DENY
   541→   541→- X-Content-Type-Options: nosniff
   542→   542→- Referrer-Policy
   543→   543→- Strict-Transport-Security (HSTS)
   544→   544→- Permissions-Policy
   545→   545→
   546→   546→### Secrets
   547→   547→- `NEXTAUTH_SECRET` — required in production. Generate with:
   548→   548→  ```bash
   549→   549→  bun -e 'console.log(require("crypto").randomBytes(32).toString("hex"))'
   550→   550→  ```
   551→   551→- `ADMIN_PASSWORD` — plaintext in `.env` only; hashed before DB storage.
   552→   552→- `.env` is gitignored. `.env.example` is the committed template.
   553→   553→
   554→   554→### Known platform-level caveat
   555→   555→The sandbox gateway (`Caddyfile`) uses an `XTransformPort` query param for port routing. This is an open-proxy-style SSRF surface at the **infra level** and is outside the application code. Flag for the platform team before any public deployment.

   774→   774→### Documentation vs. code — how to resolve disagreements
   775→   775→
   776→   776→1. **The code is always the truth.** If a doc says X but the code does Y, the doc is wrong.
   777→   777→2. **Verify in the code** before trusting any doc claim about: model names, env var names, API routes, file locations, database fields.
   778→   778→3. **Update the doc** to match the code. Do not change the code to match a stale doc unless explicitly asked.
   779→   779→4. **Never assume a model / API / package exists** without checking the installed version or the code's actual import.
