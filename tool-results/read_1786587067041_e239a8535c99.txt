     9→## 0. Quick Start — How to Run This Project
    10→
    11→> Read this section first. It covers everything from a fresh `git clone` to a running app.
    12→
    13→### 0.1 Prerequisites
    14→
    15→| Requirement | Why | Install |
    16→|---|---|---|
    17→| **Bun** (required) | The `db:seed` script and production `start` script run TypeScript / the standalone server via Bun. npm/node alone will **not** work. | https://bun.sh/docs/installation |
    18→| **Node.js 18+** | Next.js 16 needs it. Bun usually bundles a compatible runtime, but having Node helps with tooling. | https://nodejs.org/ |
    19→| **Git** | To clone the repo. | https://git-scm.com/ |
    20→
    21→> **Windows users:** Install Bun with PowerShell (`irm bun.sh/install.ps1 | iex`). All commands below work in **Git Bash** or **WSL**. If you only have CMD/PowerShell, the `dev` script still works (it's just `next dev -p 3000`), but `db:seed` needs Bun regardless.

    23→### 0.2 Step-by-Step (fresh clone)
    24→
    25→```bash
    26→# 1. Clone the repository
    27→git clone <your-repo-url> sds-chem
    28→cd sds-chem
    29→
    30→# 2. Install dependencies with Bun (do NOT use npm install)
    31→bun install
    32→
    33→# 3. Create your environment file from the template
    34→cp .env.example .env
    35→
    36→# 4. Edit .env — set these values:
    37→#    - ADMIN_EMAIL         (your admin login email)
    38→#    - ADMIN_PASSWORD      (a strong password — will be bcrypt-hashed)
    39→#    - NEXTAUTH_SECRET     (generate one — see the comment in .env.example)
    40→#    - DATABASE_URL        (already set to ./db/custom.db — leave as-is)
    41→#    - NEXTAUTH_URL        (already http://localhost:3000 — leave as-is)
    42→#
    43→#    Generate a NEXTAUTH_SECRET with:
    44→#      bun -e 'console.log(require("crypto").randomBytes(32).toString("hex"))'
    45→#      node -e "console.log(require('crypto').randomBytes(32).toString('hex'))'"
    46→
    47→# 5. Create the SQLite database + tables
    48→bun run db:push
    49→
    50→# 6. Seed the database:
    51→#    - Creates the admin user from ADMIN_EMAIL / ADMIN_PASSWORD
    52→#    - Imports the 14 seed chemicals
    53→#    - Generates a placeholder SDS PDF for each chemical
    54→bun run db:seed
    55→
    56→# 7. Start the dev server
    57→bun run dev
    58→```
    59→
    60→Open **http://localhost:3000** in your browser. You should see the chemical catalog with 14 chemicals.

    68→### 0.4 Why `npm run dev` doesn't work (and how to fix it)
    69→
    70→If you already ran `npm install` and `npm run dev`, you likely hit one of these:
    71→
    72→| Symptom | Cause | Fix |
    73→|---|---|---|
    74→| `npm run dev` fails with `tee: command not found` | Old script used a Unix-only `tee` pipe. **This has been fixed** — update to the latest code, or run `npx next dev -p 3000` directly. | `bun install` (or `npm install`) on latest code, then `bun run dev` |
    75→| `npm run db:seed` fails with `SyntaxError` or `Cannot find module` | The seed script is TypeScript run via Bun. Node/npm can't execute `.ts` files directly. | Install Bun, then run `bun run db:seed` |
    76→| App loads but shows "Database Error" / 0 chemicals | The database hasn't been created/seeded yet. | Run `bun run db:push && bun run db:seed` |
    77→| `PrismaClientInitializationError` | `DATABASE_URL` points to a path that doesn't exist on your machine. | Make sure `.env` has `DATABASE_URL=file:./db/custom.db` (relative path). Run `bun run db:push`. |
    78→| 401 on every admin API | `NEXTAUTH_SECRET` is missing or the `.env` wasn't loaded. | Set `NEXTAUTH_SECRET` in `.env`; restart `bun run dev`. |
    79→| Login fails with "Invalid email or password" | Admin user not created, or `.env` credentials don't match what's in the DB. | Run `bun run db:seed` again (it's idempotent — updates the admin to match `.env`). |

   135→## 2. High-Level Architecture
   136→
   137→```
   138→┌─────────────────────────────────────────────────────────────────┐
   139→│                        PUBLIC PWA  (/)                          │
   140→│  Catalog → Detail → Emergency views (single-route SPA, Zustand) │
   141→│  Offline-first: all reads go to Dexie (IndexedDB)               │
   142→│  Writes (favorites/notes/prefs) are LOCAL ONLY                  │
   143→└───────────────┬─────────────────────────────────┬───────────────┘
   144→                │ GET /api/sync?since=<ts>         │ GET /api/chemicals
   145→                │ GET /api/sds/[id]/download       │
   146→                ▼                                  ▼
   147→┌─────────────────────────────────────────────────────────────────┐
   148→│                     PUBLIC API (no auth)                        │
   149→│  /api/sync          delta sync (chemicals + SDS metadata)       │
   150→│  /api/chemicals     list / get chemical                         │
   151→│  /api/sds/[id]/download   stream SDS PDF                        │
   152→└───────────────┬─────────────────────────────────────────────────┘
   153→                │ Prisma
   154→                ▼
   155→┌─────────────────────────────────────────────────────────────────┐
   156→│                  PRISMA + SQLite  (source of truth)             │
   157→│  User · Chemical · SdsDocument                                  │
   158→└─────────────────────────────────────────────────────────────────┘
   159→                ▲
   160→                │ requireAdmin()  (server-side session check)
   161→┌───────────────┴─────────────────────────────────────────────────┐
   162→│                    ADMIN API (auth required)                    │
   163→│  /api/admin/dashboard          stats                            │
   164→│  /api/admin/chemicals          POST  (create)                   │
   165→│  /api/admin/chemicals/[id]     GET / PUT / DELETE               │
   166→│  /api/admin/sds                POST  (upload PDF)               │
   167→│  /api/admin/sds/[id]           DELETE (revert to placeholder)   │
   168→└───────────────┬─────────────────────────────────────────────────┘
   169→                ▲
   170→                │ NextAuth session (JWT, httpOnly cookie)
   171→┌───────────────┴─────────────────────────────────────────────────┐
   172→│                    ADMIN UI  (/admin)                           │
   173→│  /admin/login   sign-in form                                    │
   174→│  /admin         dashboard: Overview / Chemicals / SDS tabs      │
   175→│  Protected by src/middleware.ts (edge, role=ADMIN)              │
   176→└─────────────────────────────────────────────────────────────────┘
   177→```
   178→
   179→### Key principles
   180→- **Server is the source of truth** for chemical & SDS data. Client Dexie DB is a cache.
   181→- **Offline-first:** the public PWA reads from Dexie. It works fully offline after first sync.
   182→- **Delta sync:** clients ask for changes since their last sync timestamp — never the whole DB.
   183→- **SDS PDFs are versioned & cached** as Blobs in IndexedDB; only re-downloaded when version changes.
   184→- **User preferences (favorites/notes) stay local** — never sent to the server, never overwritten.
   185→- **Admin authorization is server-side** in every admin API route (`requireAdmin()`). The edge middleware is defense-in-depth only.

   325→## 5. Client Database (Dexie v2)
   326→
   327→```
   328→chemicals      : ChemicalRecord  (keyPath: id)        + indexes on casNumber, department, etc.
   329→sdsDocuments   : SdsMeta          (keyPath: chemicalId)
   330→sdsBlobs       : { chemicalId, version, blob, fetchedAt }   ← SDS PDF Blob cache
   331→syncMeta       : { key, value }   ← lastSyncTimestamp, syncMutex, etc.
   332→locations      : LaboratoryLocation
   333→preferences    : UserPreferences  (favorites, notes, theme — LOCAL ONLY)
   334→```
   335→
   336→**Why two stores?** `sdsDocuments` holds metadata (small, synced as JSON). `sdsBlobs` holds the actual PDF Blob (large, only re-fetched when `version` changes).

   340→## 6. API Reference
   341→
   342→### Public (no auth)
   343→| Method | Path | Purpose |
   344→|---|---|---|
   345→| GET | `/api/sync?since=<epoch-ms>` | Delta sync. Returns `{ chemicals: [...], sdsDocuments: [...], deletedChemicalIds: [...], serverTime }`. Only records with `updatedAt > since` (or `deletedAt > since`) are returned. |
   346→| GET | `/api/chemicals` | List all non-deleted chemicals (metadata only, no PDF). |
   347→| GET | `/api/chemicals/[id]` | Single chemical. |
   348→| GET | `/api/sds/[id]/download` | Stream the SDS PDF for chemical `[id]`. Sets `Content-Type: application/pdf`. Used by both the public PWA (caches Blob) and admin "View". |
   349→
   350→### Admin (auth required — `requireAdmin()`)
   351→| Method | Path | Purpose |
   352→|---|---|---|
   353→| GET | `/api/admin/dashboard` | Stats: total chemicals, SDS coverage, department distribution, recent updates. |
   354→| POST | `/api/admin/chemicals` | Create chemical. Auto-creates a placeholder `SdsDocument`. Body validated by zod. |
   355→| GET | `/api/admin/chemicals/[id]` | Read single (admin view). |
   356→| PUT | `/api/admin/chemicals/[id]` | Update. Bumps `serverVersion`. Sets `updatedById`. |
   357→| DELETE | `/api/admin/chemicals/[id]` | Soft-delete (`deletedAt = now`). Cascade-soft-deletes the SDS. |
   358→| POST | `/api/admin/sds` | Upload / replace SDS PDF. Multipart form. Validates magic bytes + MIME + extension + size. Stores with UUID filename. Increments `version`, sets `status = available`. |
   359→| DELETE | `/api/admin/sds/[id]` | Revert to placeholder. Removes the uploaded file, resets `status = placeholder`, increments `version`. |
   360→
   361→### Auth
   362→| Method | Path | Purpose |
   363→|---|---|---|
   364→| POST | `/api/auth/callback/credentials` | NextAuth credentials sign-in. |
   365→| GET/POST | `/api/auth/*` | NextAuth session / csrf / signout handlers. |

   369→## 7. Sync Engine (`src/lib/sync-engine.ts`)
   370→
   371→### Trigger points
   372→1. **App startup** — fires once Dexie is initialized.
   373→2. **Offline → online transition** — `use-online-status` hook notifies the engine.
   374→3. **Periodic** — runs every few minutes while online.
   375→
   376→### Algorithm
   377→```
   378→1. Acquire mutex (in Dexie.syncMeta) — prevents concurrent syncs across tabs.
   379→2. Read lastSyncTimestamp from syncMeta.
   380→3. GET /api/sync?since=<lastSyncTimestamp>.
   381→4. For each chemical in response:
   382→   - If deleted (deletedAt > since) → remove from Dexie.chemicals.
   383→   - Else → upsert into Dexie.chemicals.
   384→5. For each sdsDocument in response:
   385→   - Upsert metadata into Dexie.sdsDocuments.
   386→   - Compare version with Dexie.sdsBlobs.
   387→     - If version unchanged AND blob exists → skip (no re-download).
   388→     - If version changed OR blob missing → GET /api/sds/[id]/download,
   389→       store Blob in Dexie.sdsBlobs with new version.
   390→6. Persist new lastSyncTimestamp = response.serverTime.
   391→7. Release mutex. Update Zustand sync status.
   392→```
   393→
   394→### Rate limiting
   395→A minimum interval between sync attempts prevents hammering the server on flaky connections. Manual retry from the UI bypasses the interval once.
   396→
   397→### Status states (the `SyncStatus` type)
   398→| State | Meaning |
   399→|---|---|
   400→| `offline` | Navigator reports offline. No sync attempts. |
   401→| `syncing` | A sync is in progress. |
   402→| `synced` | Last sync completed successfully and we're online. |
   403→| `local-changes` | *(reserved)* user has local-only changes that couldn't be pushed (currently preferences only — always local). |
   404→| `error` | Last sync attempt failed. UI shows a retry button. |
   405→
   406→### Conflict resolution
   407→- **Chemical / SDS data:** server-wins. The latest `updatedAt` always wins.
   408→- **User preferences / favorites / notes:** local-only, never synced, never overwritten.

   412→## 8. Security Model
   413→
   414→### Authentication
   415→- NextAuth Credentials provider.
   416→- Passwords hashed with **bcrypt (12 rounds)** — never stored or logged in plaintext.
   417→- JWT session strategy, 30-day max age.
   418→- Cookies: `httpOnly`, `sameSite=lax`, `secure` in production (`__Secure-` prefix).
   419→
   420→### Authorization (defense in depth)
   421→1. **Edge middleware** (`src/middleware.ts`) — blocks `/admin/*` (except `/admin/login`) unless the JWT has `role === "ADMIN"`. Fast, runs at the edge.
   422→2. **Server-side guard** (`requireAdmin()` in `src/lib/session.ts`) — every admin API route calls this. Returns 401 if no valid admin session. This is the real enforcement layer; the middleware is just a UX optimization / defense-in-depth.
   423→
   424→### SDS file upload safety
   425→- **Magic-byte validation** — the file must start with `%PDF-` (PDF signature). Renamed non-PDFs are rejected.
   426→- **MIME type check** — must be `application/pdf`.
   427→- **Extension check** — must end in `.pdf`.
   428→- **Size limit** — enforced (see `validation.ts`).
   429→- **Filename handling** — user-supplied filename is stored only for display/download. The actual stored file is named `<uuid>.pdf` under `storage/`. No path traversal possible.
   430→- **No path exposure** — `storageKey` is a UUID, never the original path.
   431→
   432→### Input validation
   433→- All admin chemical inputs validated with **zod** schemas before reaching Prisma.
   434→- Prisma parameterizes all queries — no raw SQL, no SQL injection surface.
   435→
   436→### Security headers (`next.config.ts`)
   437→- Content-Security-Policy
   438→- X-Frame-Options: DENY
   439→- X-Content-Type-Options: nosniff
   440→- Referrer-Policy
   441→- Strict-Transport-Security (HSTS)
   442→- Permissions-Policy
   443→
   444→### Secrets
   445→- `NEXTAUTH_SECRET` — required in production. Generate with:
   446→  ```bash
   447→  bun -e 'console.log(require("crypto").randomBytes(32).toString("hex"))'
   448→  ```
   449→- `ADMIN_PASSWORD` — plaintext in `.env` only; hashed before DB storage.
   450→- `.env` is gitignored. `.env.example` is the committed template.
   451→
   452→### Known platform-level caveat

   586→## 14. Troubleshooting (Developer)
   587→
   588→| Symptom | Cause | Fix |
   589→|---|---|---|
   590→| `PrismaClientInitializationError` | DB file missing or path wrong | Check `DATABASE_URL` in `.env`; run `bun run db:push` |
   591→| `bun run db:seed` does nothing | Admin already exists with same email | It's idempotent — it upserts. Check `SELECT * FROM User`. |
   592→| 401 on every admin API even when "logged in" | Session cookie not sent (cross-origin / different port) | Ensure requests use relative paths; in this sandbox use `XTransformPort` for cross-service calls |
   593→| SDS upload 413 | File too large | Check the size limit in `src/lib/validation.ts` / reverse proxy |
   594→| Dexie schema version conflict | Old client DB version | Bump Dexie schema version in `src/lib/local-db.ts` with an upgrade function |
   595→| Service worker not updating | Old SW cached | Bump `CACHE_VERSION` in `public/sw.js`; user will get new SW on next load |
   596→| Preview shows blank "Z" screen | Dev server not running | `bun run dev` (this is the most common "it's loading" report) |
