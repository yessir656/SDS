   512→   512→## 7. Sync Engine (`src/lib/sync-engine.ts`)
   513→   513→
   514→   514→### Trigger points
   515→   515→1. **App startup** — fires once Dexie is initialized.
   516→   516→2. **Offline → online transition** — `use-online-status` hook notifies the engine.
   517→   517→3. **Periodic** — runs every few minutes while online.
   518→   518→
   519→   519→### Algorithm
   520→   520→```
   521→   521→1. Acquire mutex (in Dexie.syncMeta) — prevents concurrent syncs across tabs.
   522→   522→2. Read lastSyncTimestamp from syncMeta.
   523→   523→3. GET /api/sync?since=<lastSyncTimestamp>.
   524→   524→4. For each chemical in response:
   525→   525→   - If deleted (deletedAt > since) → remove from Dexie.chemicals.
   526→   526→   - Else → upsert into Dexie.chemicals.
   527→   527→5. For each sdsDocument in response:
   528→   528→   - Upsert metadata into Dexie.sdsDocuments.
   529→   529→   - Compare version with Dexie.sdsBlobs.
   530→   530→     - If version unchanged AND blob exists → skip (no re-download).
   531→   531→     - If version changed OR blob missing → GET /api/sds/[id]/download,
   532→   532→       store Blob in Dexie.sdsBlobs with new version.
   533→   533→6. Persist new lastSyncTimestamp = response.serverTime.
   534→   534→7. Release mutex. Update Zustand sync status.
   535→   535→```
   536→   536→
   537→   537→### Rate limiting
   538→   538→A minimum interval between sync attempts prevents hammering the server on flaky connections. Manual retry from the UI bypasses the interval once.
   539→   539→
   540→   540→### Status states (the `SyncStatus` type)
   541→   541→| State | Meaning |
   542→   542→|---|---|
   543→   543→| `offline` | Navigator reports offline. No sync attempts. |
   544→   544→| `syncing` | A sync is in progress. |
   545→   545→| `synced` | Last sync completed successfully and we're online. |
   546→   546→| `local-changes` | *(reserved)* user has local-only changes that couldn't be pushed (currently preferences only — always local). |
   547→   547→| `error` | Last sync attempt failed. UI shows a retry button. |
   548→   548→
   549→   549→### Conflict resolution
   550→   550→- **Chemical / SDS data:** server-wins. The latest `updatedAt` always wins.
   551→   551→- **User preferences / favorites / notes:** local-only, never synced, never overwritten.

   555→   555→## 8. Security Model
   556→   556→
   557→   557→### Authentication
   558→   558→- NextAuth Credentials provider.
   559→   559→- **3-tier role hierarchy**: `SUPER_ADMIN` > `ADMIN` > `USER`. Only `SUPER_ADMIN` and `ADMIN` can sign in to `/admin/*`; `USER` is reserved for the public PWA and is rejected by `authorize()`.
   560→   560→- Disabled accounts (`disabled === true`) cannot sign in.
   561→   561→- Passwords hashed with **bcrypt (12 rounds)** — never stored or logged in plaintext.
   562→   562→- JWT session strategy, 30-day max age. The JWT carries `id`, `role`, and `passwordChangeRequired`; the `session` callback copies them onto `session.user`.
   563→   563→- On `useSession().update()` (trigger `"update"`), the `jwt` callback re-fetches `passwordChangeRequired` + `role` from the DB so a just-completed password change is reflected without a fresh sign-in.
   564→   564→- Cookies: `httpOnly`, `sameSite=lax`, `secure` in production (`__Secure-` prefix).
   565→   565→
   566→   566→### Authorization (defense in depth)
   567→   567→1. **Edge middleware** (`src/middleware.ts`) — blocks `/admin/*` (except `/admin/login`) unless the JWT has `role === "SUPER_ADMIN" || role === "ADMIN"`. Fast, runs at the edge. (Super-admin-only routes enforce the stricter check server-side via `requireSuperAdmin()`.)
   568→   568→2. **`requireAdmin()`** (in `src/lib/session.ts`) — every admin API route for chemicals / SDS / dashboard / change-password-adjacent features calls this. Returns 401 if the session is missing or the user is not `ADMIN` / `SUPER_ADMIN`. **Also returns 401 if the user has `passwordChangeRequired === true`** — defense-in-depth so a bypassed client guard still can't reach the API.
   569→   569→3. **`requireSuperAdmin()`** (in `src/lib/session.ts`) — same shape as `requireAdmin()` but additionally requires `role === "SUPER_ADMIN"`. Used by user-management, audit-log, and system-settings routes. Also blocks `passwordChangeRequired` users.
   570→   570→4. **`PasswordGuard`** client component (`src/components/admin/password-guard.tsx`) — mounted in the admin layout. Uses `useSession()` + `usePathname()`; if the current path is NOT `/admin/login` and NOT `/admin/change-password`, and the session has `passwordChangeRequired === true`, hard-redirects to `/admin/change-password`.
   571→   571→
   572→   572→### Audit log
   573→   573→Every chemical / SDS / user / system mutation is logged via `logAction()` in `src/lib/audit.ts`.
   574→   574→- **Fire-and-forget**: `logAction()` wraps its `db.auditLog.create()` in a `try/catch` and only logs to `stderr` on failure. An audit-log problem can **never** break the main operation the user is trying to perform.
   575→   575→- **Captures**: `actorId`, `actorEmail` (denormalized so the row survives user deletion), `action` (dotted, e.g. `chemical.create`, `user.disable`, `system.test-ai`), `entityType`, `entityId`, `summary`, `before` / `after` JSON snapshots (built via `snapshotChemical()` for chemicals), and a best-effort `ipAddress` (from `x-forwarded-for` / `x-real-ip` via `auditContext()`).
   576→   576→- **Storage**: `AuditLog` table (append-only — no update / delete endpoints exist). Indexed on `createdAt`, `actorId`, `[entityType, entityId]`, `action`.
   577→   577→- **Viewer**: `GET /api/admin/audit` (SUPER_ADMIN only), cursor-paginated. UI: `src/components/admin/audit-log-viewer.tsx`.
   578→   578→
   579→   579→### Password change enforcement (triple-layered)
   580→   580→When a super-admin creates a user with a temporary password (or resets an existing user's password), `passwordChangeRequired` is set to `true`. The user is then forced to change their password on next login via three independent layers:
   581→   581→1. **Client-side guard** — `PasswordGuard` (`src/components/admin/password-guard.tsx`) redirects to `/admin/change-password` as soon as the session loads. Bypassing this is possible (disable JS), so it's UX + first line of defense only.
   582→   582→2. **Server-side guard** — both `requireAdmin()` and `requireSuperAdmin()` return 401 when `passwordChangeRequired === true`. So a user with the flag set cannot call any admin API route except the change-password endpoint.
   583→   583→3. **Verified current password** — `POST /api/admin/change-password` calls `getServerSession` directly (NOT `requireAdmin()`), verifies `currentPassword` against the bcrypt hash, rejects if `newPassword === currentPassword`, hashes the new password, sets `passwordChangeRequired=false`, and audit-logs `user.password-change`. The client then calls `useSession().update()` so the JWT refreshes without a fresh sign-in.
   584→   584→
   585→   585→The change-password route is the **only** admin API route that does not go through `requireAdmin()` / `requireSuperAdmin()` — by design, so the flag-bearer can still escape the gate.
   586→   586→
   587→   587→### SDS file upload safety
   588→   588→- **Magic-byte validation** — the file must start with `%PDF-` (PDF signature). Renamed non-PDFs are rejected.
   589→   589→- **MIME type check** — must be `application/pdf`.
   590→   590→- **Extension check** — must end in `.pdf`.
   591→   591→- **Size limit** — enforced (see `validation.ts`).
   592→   592→- **Filename handling** — user-supplied filename is stored only for display/download. The actual stored file is named `<uuid>.pdf` under `storage/`. No path traversal possible.
   593→   593→- **No path exposure** — `storageKey` is a UUID, never the original path.
   594→   594→
   595→   595→### Input validation
   596→   596→- All admin chemical inputs validated with **zod** schemas before reaching Prisma.
   597→   597→- Prisma parameterizes all queries — no raw SQL, no SQL injection surface.
   598→   598→
   599→   599→### Security headers (`next.config.ts`)
   600→   600→- Content-Security-Policy
   601→   601→- X-Frame-Options: DENY
   602→   602→- X-Content-Type-Options: nosniff
   603→   603→- Referrer-Policy
   604→   604→- Strict-Transport-Security (HSTS)
   605→   605→- Permissions-Policy
   606→   606→
   607→   607→### Secrets
   608→   608→- `NEXTAUTH_SECRET` — required in production. Generate with:
   609→   609→  ```bash
   610→   610→  bun -e 'console.log(require("crypto").randomBytes(32).toString("hex"))'
   611→   611→  ```
   612→   612→- `ADMIN_PASSWORD` — plaintext in `.env` only; hashed before DB storage.
   613→   613→- `.env` is gitignored. `.env.example` is the committed template.
   614→   614→
   615→   615→### Known platform-level caveat
   616→   616→The sandbox gateway (`Caddyfile`) uses an `XTransformPort` query param for port routing. This is an open-proxy-style SSRF surface at the **infra level** and is outside the application code. Flag for the platform team before any public deployment.

   850→   850→### Documentation vs. code — how to resolve disagreements
   851→   851→
   852→   852→1. **The code is always the truth.** If a doc says X but the code does Y, the doc is wrong.
   853→   853→2. **Verify in the code** before trusting any doc claim about: model names, env var names, API routes, file locations, database fields.
   854→   854→3. **Update the doc** to match the code. Do not change the code to match a stale doc unless explicitly asked.
   855→   855→4. **Never assume a model / API / package exists** without checking the installed version or the code's actual import.
