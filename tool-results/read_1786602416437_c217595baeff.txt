     9→## 0. Quick Start — How to Run This Project
    10→
    11→> Read this section first. It covers everything from a fresh `git clone` to a running app.
    12→
    13→### 0.1 Prerequisites
    14→
    15→| Requirement | Why | Install |
    16→|---|---|---|
    17→| **Bun** (required) | The `db:seed` script and production `start` script run TypeScript / the standalone server via Bun. npm/node alone will **not** work. | https://bun.sh/docs/installation |
    18→| **Node.js 18+** | Next.js 16 needs it. Bun usually bundles a compatible runtime, but having Node helps with tooling. | https://nodejs.org/ |
    19→| **Git** | To clone the repo. | https://git-scm.com/ |
    20→
    21→> **Windows users:** Install Bun with PowerShell (`irm bun.sh/install.ps1 | iex`). All commands below work in **Git Bash** or **WSL**. If you only have CMD/PowerShell, the `dev` script still works (it's just `next dev -p 3000`), but `db:seed` needs Bun regardless.
    22→
    23→### 0.2 Step-by-Step (fresh clone)
    24→
    25→```bash
    26→# 1. Clone the repository
    27→git clone <your-repo-url> sds-chem
    28→cd sds-chem
    29→
    30→# 2. Install dependencies with Bun (do NOT use npm install)
    31→bun install
    32→
    33→# 3. Create your environment file from the template
    34→cp .env.example .env
    35→
    36→# 4. Edit .env — set these values:
    37→#    - ADMIN_EMAIL         (your admin login email)
    38→#    - ADMIN_PASSWORD      (a strong password — will be bcrypt-hashed)
    39→#    - NEXTAUTH_SECRET     (generate one — see the comment in .env.example)
    40→#    - DATABASE_URL        (already set to ./db/custom.db — leave as-is)
    41→#    - NEXTAUTH_URL        (already http://localhost:3000 — leave as-is)
    42→#
    43→#    Generate a NEXTAUTH_SECRET with:
    44→#      bun -e 'console.log(require("crypto").randomBytes(32).toString("hex"))'
    45→#      node -e "console.log(require('crypto').randomBytes(32).toString('hex'))'"
    46→
    47→# 5. Create the SQLite database + tables
    48→bun run db:push
    49→
    50→# 6. Seed the database:
    51→#    - Creates the admin user from ADMIN_EMAIL / ADMIN_PASSWORD
    52→#    - Imports the 14 seed chemicals
    53→#    - Generates a placeholder SDS PDF for each chemical
    54→bun run db:seed
    55→
    56→# 7. Start the dev server
    57→bun run dev
    58→```
    59→
    60→Open **http://localhost:3000** in your browser. You should see the chemical catalog with 14 chemicals.
    61→
    62→### 0.3 Accessing the admin dashboard
    63→
    64→1. Go to **http://localhost:3000/admin/login**
    65→2. Sign in with the `ADMIN_EMAIL` / `ADMIN_PASSWORD` you set in `.env`.

    68→### 0.4 Why `npm run dev` doesn't work (and how to fix it)
    69→
    70→If you already ran `npm install` and `npm run dev`, you likely hit one of these:
    71→
    72→| Symptom | Cause | Fix |
    73→|---|---|---|
    74→| `npm run dev` fails with `tee: command not found` | Old script used a Unix-only `tee` pipe. **This has been fixed** — update to the latest code, or run `npx next dev -p 3000` directly. | `bun install` (or `npm install`) on latest code, then `bun run dev` |
    75→| `npm run db:seed` fails with `SyntaxError` or `Cannot find module` | The seed script is TypeScript run via Bun. Node/npm can't execute `.ts` files directly. | Install Bun, then run `bun run db:seed` |
    76→| App loads but shows "Database Error" / 0 chemicals | The database hasn't been created/seeded yet. | Run `bun run db:push && bun run db:seed` |
    77→| `PrismaClientInitializationError` | `DATABASE_URL` points to a path that doesn't exist on your machine. | Make sure `.env` has `DATABASE_URL=file:./db/custom.db` (relative path). Run `bun run db:push`. |
    78→| 401 on every admin API | `NEXTAUTH_SECRET` is missing or the `.env` wasn't loaded. | Set `NEXTAUTH_SECRET` in `.env`; restart `bun run dev`. |
    79→| Login fails with "Invalid email or password" | Admin user not created, or `.env` credentials don't match what's in the DB. | Run `bun run db:seed` again (it's idempotent — updates the admin to match `.env`). |
    80→

    86→# Remove npm's node_modules and lockfile
    87→rm -rf node_modules package-lock.json
    88→

    90→bun install

   135→## 2. High-Level Architecture
   136→
   137→```
   138→┌─────────────────────────────────────────────────────────────────┐
   139→│                        PUBLIC PWA  (/)                          │
   140→│  Catalog → Detail → Emergency views (single-route SPA, Zustand) │
   141→│  Offline-first: all reads go to Dexie (IndexedDB)               │
   142→│  Writes (favorites/notes/prefs) are LOCAL ONLY                  │
   143→└───────────────┬─────────────────────────────────┬───────────────┘
   144→                │ GET /api/sync?since=<ts>         │ GET /api/chemicals
   145→                │ GET /api/sds/[id]/download       │
   146→                ▼                                  ▼
   147→┌─────────────────────────────────────────────────────────────────┐
   148→│                     PUBLIC API (no auth)                        │
   149→│  /api/sync          delta sync (chemicals + SDS metadata)       │
   150→│  /api/chemicals     list / get chemical                         │
   151→│  /api/sds/[id]/download   stream SDS PDF                        │
   152→└───────────────┬─────────────────────────────────────────────────┘
   153→                │ Prisma
   154→                ▼
   155→┌─────────────────────────────────────────────────────────────────┐
   156→│                  PRISMA + SQLite  (source of truth)             │
   157→│  User · Chemical · SdsDocument                                  │
   158→└─────────────────────────────────────────────────────────────────┘
   159→                ▲
   160→                │ requireAdmin()  (server-side session check)
   161→┌───────────────┴─────────────────────────────────────────────────┐
   162→│                    ADMIN API (auth required)                    │
   163→│  /api/admin/dashboard          stats                            │
   164→│  /api/admin/chemicals          POST  (create)                   │
   165→│  /api/admin/chemicals/[id]     GET / PUT / DELETE               │
   166→│  /api/admin/sds                POST  (upload PDF)               │
   167→│  /api/admin/sds/[id]           DELETE (revert to placeholder)   │
   168→└───────────────┬─────────────────────────────────────────────────┘
   169→                ▲
   170→                │ NextAuth session (JWT, httpOnly cookie)
   171→┌───────────────┴─────────────────────────────────────────────────┐
   172→│                    ADMIN UI  (/admin)                           │
   173→│  /admin/login   sign-in form                                    │
   174→│  /admin         dashboard: Overview / Chemicals / SDS tabs      │
   175→│  Protected by src/middleware.ts (edge, role=ADMIN)              │
   176→└─────────────────────────────────────────────────────────────────┘
   177→```
   178→
   179→### Key principles
   180→- **Server is the source of truth** for chemical & SDS data. Client Dexie DB is a cache.
   181→- **Offline-first:** the public PWA reads from Dexie. It works fully offline after first sync.
   182→- **Delta sync:** clients ask for changes since their last sync timestamp — never the whole DB.
   183→- **SDS PDFs are versioned & cached** as Blobs in IndexedDB; only re-downloaded when version changes.
   184→- **User preferences (favorites/notes) stay local** — never sent to the server, never overwritten.
   185→- **Admin authorization is server-side** in every admin API route (`requireAdmin()`). The edge middleware is defense-in-depth only.

   279→
   280→### `User` — admin accounts only
   281→| Field | Type | Notes |
   282→|---|---|---|
   283→| id | String (cuid) | PK |
   284→| email | String | unique |
   285→| passwordHash | String | bcrypt (12 rounds) |
   286→| name | String? | optional display name |
   287→| role | String | `"ADMIN"` or `"USER"` (only ADMIN can log in) |
   288→| createdAt / updatedAt | DateTime | |
   289→| Relations | `SdsDocument[] uploadedSds`, `Chemical[] updatedChemicals` | audit trail |
   290→

   292→| Field | Type | Notes |
   293→|---|---|---|
   294→| id | String | PK (stable slug, e.g. `chem-acetone`) |
   295→| casNumber, chemicalName, formula | String | identifiers |
   296→| tradeName, manufacturer, supplier | String | provenance |
   297→| signalWord | String | `"danger"` / `"warning"` |
   298→| hazardClasses | String | JSON-encoded `HazardClass[]` |
   299→| ghsPictograms | String | JSON-encoded `GhsPictogram[]` |
   300→| storageLocation, department | String | physical location |
   301→| safetyInstructions | String | |
   302→| version | String | SDS document version label (e.g. `"1.4"`) |
   303→| emergencyContact | String | |
   304→| personalProtectiveEquipment | String | JSON array |
   305→| firstAidMeasures, firefightingMeasures, accidentalReleaseMeasures | String | SDS sections 4/5/6 |
   306→| **serverVersion** | Int | **sync key** — incremented on every update |
   307→| createdAt, updatedAt | DateTime | |
   308→| **deletedAt** | DateTime? | **soft delete** — sync propagates deletes |
   309→| updatedById | String? | FK → User (audit) |
   310→| Relations | `SdsDocument? sdsDocument` | 1:1 |

   325→| uploadedById | String? | FK → User (audit) |
   326→| createdAt, updatedAt | DateTime | |
   327→
   328→Indexes: `updatedAt`, `status`.

   332→## 5. Client Database (Dexie v2)
   333→
   334→```
   335→chemicals      : ChemicalRecord  (keyPath: id)        + indexes on casNumber, department, etc.
   336→sdsDocuments   : SdsMeta          (keyPath: chemicalId)
   337→sdsBlobs       : { chemicalId, version, blob, fetchedAt }   ← SDS PDF Blob cache
   338→syncMeta       : { key, value }   ← lastSyncTimestamp, syncMutex, etc.
   339→locations      : LaboratoryLocation
   340→preferences    : UserPreferences  (favorites, notes, theme — LOCAL ONLY)
   341→```
   342→
   343→**Why two stores?** `sdsDocuments` holds metadata (small, synced as JSON). `sdsBlobs` holds the actual PDF Blob (large, only re-fetched when `version` changes).

   347→## 6. API Reference
   348→
   349→### Public (no auth)
   350→| Method | Path | Purpose |
   351→|---|---|---|
   352→| GET | `/api/sync?since=<epoch-ms>` | Delta sync. Returns `{ chemicals: [...], sdsDocuments: [...], deletedChemicalIds: [...], serverTime }`. Only records with `updatedAt > since` (or `deletedAt > since`) are returned. |
   353→| GET | `/api/chemicals` | List all non-deleted chemicals (metadata only, no PDF). |
   354→| GET | `/api/chemicals/[id]` | Single chemical. |
   355→| GET | `/api/sds/[id]/download` | Stream the SDS PDF for chemical `[id]`. Sets `Content-Type: application/pdf`. Used by both the public PWA (caches Blob) and admin "View". |
   356→
   357→### Admin (auth required — `requireAdmin()`)
   358→| Method | Path | Purpose |
   359→|---|---|---|
   360→| GET | `/api/admin/dashboard` | Stats: total chemicals, SDS coverage, department distribution, recent updates. |
   361→| POST | `/api/admin/chemicals` | Create chemical. Auto-creates a placeholder `SdsDocument`. Body validated by zod. |
   362→| GET | `/api/admin/chemicals/[id]` | Read single (admin view). |
   363→| PUT | `/api/admin/chemicals/[id]` | Update. Bumps `serverVersion`. Sets `updatedById`. |
   364→| DELETE | `/api/admin/chemicals/[id]` | Soft-delete (`deletedAt = now`). Cascade-soft-deletes the SDS. |
   365→| POST | `/api/admin/sds` | Upload / replace SDS PDF. Multipart form. Validates magic bytes + MIME + extension + size. Stores with UUID filename. Increments `version`, sets `status = available`. |
   366→| DELETE | `/api/admin/sds/[id]` | Revert to placeholder. Removes the uploaded file, resets `status = placeholder`, increments `version`. |
   367→| POST | `/api/admin/sds/extract` | **AI auto-fill.** Accepts an SDS PDF (multipart), rasterizes first 5 pages to PNG, sends to the configured VLM provider (`src/lib/ai-vlm.ts`), parses + sanitizes the JSON response, returns `{ success, data }`. 60s timeout. See §6A. |
   368→
   369→### Auth
   370→| Method | Path | Purpose |
   371→|---|---|---|
   372→| POST | `/api/auth/callback/credentials` | NextAuth credentials sign-in. |
   373→| GET/POST | `/api/auth/*` | NextAuth session / csrf / signout handlers. |

   377→## 6A. AI Auto-Fill Architecture (VLM Provider Abstraction)
   378→
   379→The "Auto-fill from PDF" feature reads an uploaded SDS PDF using a vision-language
   380→model (VLM) and returns structured JSON fields. The provider is swappable via the
   381→`AI_PROVIDER` env var so the same code works on the sandbox (free in-house AI) and
   382→on a local machine (free Google Gemini tier).
   383→
   384→### Request flow
   385→
   386→```
   387→Admin UI (chemical-manager.tsx)
   388→  └─ user clicks "Auto-fill from PDF", selects a .pdf file
   389→  └─ POST /api/admin/sds/extract  (multipart: file=...)
   390→       │
   391→       ├─ requireAdmin()                          ← server-side authz
   392→       ├─ validate file (magic bytes %PDF- + MIME + .pdf + size)
   393→       ├─ assertProviderConfigured(provider)      ← fail fast if key missing
   394→       ├─ rasterizePdfToPngs(buffer, {maxPages:5, scale:2})   ← src/lib/pdf-rasterize.ts
   395→       │     └─ pdfjs-dist + @napi-rs/canvas (pure JS, no Poppler)
   396→       ├─ callVlm(pageImages, EXTRACTION_PROMPT)  ← src/lib/ai-vlm.ts
   397→       │     ├─ AI_PROVIDER=zai       → z-ai-web-dev-sdk (glm-4.6v)   [sandbox default]
   398→       │     ├─ AI_PROVIDER=gemini    → @google/generative-ai (gemini-3.6-flash)
   399→       │     ├─ AI_PROVIDER=openai    → openai SDK (gpt-4o-mini)
   400→       │     └─ AI_PROVIDER=anthropic → @anthropic-ai/sdk (claude-3-5-sonnet)
   401→       ├─ extractJson(rawResponse)                 ← strip markdown fences
   402→       ├─ JSON.parse + sanitize (enum filter, trim, dedupe)
   403→       └─ return { success: true, data: {…15 fields…} }
   404→  └─ frontend merges fields into the chemical form (preserves the manual `id` field)
   405→```
   406→
   407→### Provider selection (`src/lib/ai-vlm.ts`)
   408→
   409→| `AI_PROVIDER` | SDK package | Default model | Where it works |
   410→|---|---|---|---|
   411→| `zai` (default) | `z-ai-web-dev-sdk` (pre-installed) | `glm-4.6v` | **Z.ai sandbox only** — auto-configured via `/etc/.z-ai-config`. Does NOT work on a local machine. |
   412→| `gemini` | `@google/generative-ai` (pre-installed, v0.24.1) | `gemini-3.6-flash` | Local dev / production. Free tier: 1,500 req/day. |
   413→| `openai` | `openai` (NOT installed — `bun add openai`) | `gpt-4o-mini` | Local dev / production. Paid. |
   414→| `anthropic` | `@anthropic-ai/sdk` (NOT installed — `bun add @anthropic-ai/sdk`) | `claude-3-5-sonnet-20241022` | Local dev / production. Paid. |
   415→
   416→### Gemini configuration (verified)
   417→
   418→| Item | Value |
   419→|---|---|

   471→## 7. Sync Engine (`src/lib/sync-engine.ts`)
   472→
   473→### Trigger points
   474→1. **App startup** — fires once Dexie is initialized.
   475→2. **Offline → online transition** — `use-online-status` hook notifies the engine.
   476→3. **Periodic** — runs every few minutes while online.
   477→
   478→### Algorithm
   479→```
   480→1. Acquire mutex (in Dexie.syncMeta) — prevents concurrent syncs across tabs.
   481→2. Read lastSyncTimestamp from syncMeta.
   482→3. GET /api/sync?since=<lastSyncTimestamp>.
   483→4. For each chemical in response:
   484→   - If deleted (deletedAt > since) → remove from Dexie.chemicals.
   485→   - Else → upsert into Dexie.chemicals.
   486→5. For each sdsDocument in response:
   487→   - Upsert metadata into Dexie.sdsDocuments.
   488→   - Compare version with Dexie.sdsBlobs.
   489→     - If version unchanged AND blob exists → skip (no re-download).
   490→     - If version changed OR blob missing → GET /api/sds/[id]/download,
   491→       store Blob in Dexie.sdsBlobs with new version.
   492→6. Persist new lastSyncTimestamp = response.serverTime.
   493→7. Release mutex. Update Zustand sync status.
   494→```
   495→
   496→### Rate limiting
   497→A minimum interval between sync attempts prevents hammering the server on flaky connections. Manual retry from the UI bypasses the interval once.
   498→
   499→### Status states (the `SyncStatus` type)
   500→| State | Meaning |
   501→|---|---|
   502→| `offline` | Navigator reports offline. No sync attempts. |
   503→| `syncing` | A sync is in progress. |
   504→| `synced` | Last sync completed successfully and we're online. |
   505→| `local-changes` | *(reserved)* user has local-only changes that couldn't be pushed (currently preferences only — always local). |
   506→| `error` | Last sync attempt failed. UI shows a retry button. |
   507→
   508→### Conflict resolution
   509→- **Chemical / SDS data:** server-wins. The latest `updatedAt` always wins.
   510→- **User preferences / favorites / notes:** local-only, never synced, never overwritten.

   514→## 8. Security Model
   515→
   516→### Authentication
   517→- NextAuth Credentials provider.
   518→- Passwords hashed with **bcrypt (12 rounds)** — never stored or logged in plaintext.
   519→- JWT session strategy, 30-day max age.
   520→- Cookies: `httpOnly`, `sameSite=lax`, `secure` in production (`__Secure-` prefix).
   521→
   522→### Authorization (defense in depth)
   523→1. **Edge middleware** (`src/middleware.ts`) — blocks `/admin/*` (except `/admin/login`) unless the JWT has `role === "ADMIN"`. Fast, runs at the edge.
   524→2. **Server-side guard** (`requireAdmin()` in `src/lib/session.ts`) — every admin API route calls this. Returns 401 if no valid admin session. This is the real enforcement layer; the middleware is just a UX optimization / defense-in-depth.
   525→
   526→### SDS file upload safety
   527→- **Magic-byte validation** — the file must start with `%PDF-` (PDF signature). Renamed non-PDFs are rejected.
   528→- **MIME type check** — must be `application/pdf`.
   529→- **Extension check** — must end in `.pdf`.
   530→- **Size limit** — enforced (see `validation.ts`).
   531→- **Filename handling** — user-supplied filename is stored only for display/download. The actual stored file is named `<uuid>.pdf` under `storage/`. No path traversal possible.
   532→- **No path exposure** — `storageKey` is a UUID, never the original path.
   533→
   534→### Input validation
   535→- All admin chemical inputs validated with **zod** schemas before reaching Prisma.
   536→- Prisma parameterizes all queries — no raw SQL, no SQL injection surface.
   537→
   538→### Security headers (`next.config.ts`)
   539→- Content-Security-Policy
   540→- X-Frame-Options: DENY
   541→- X-Content-Type-Options: nosniff
   542→- Referrer-Policy
   543→- Strict-Transport-Security (HSTS)
   544→- Permissions-Policy
   545→
   546→### Secrets
   547→- `NEXTAUTH_SECRET` — required in production. Generate with:
   548→  ```bash
   549→  bun -e 'console.log(require("crypto").randomBytes(32).toString("hex"))'
   550→  ```
   551→- `ADMIN_PASSWORD` — plaintext in `.env` only; hashed before DB storage.
   552→- `.env` is gitignored. `.env.example` is the committed template.
   553→
   554→### Known platform-level caveat
   555→The sandbox gateway (`Caddyfile`) uses an `XTransformPort` query param for port routing. This is an open-proxy-style SSRF surface at the **infra level** and is outside the application code. Flag for the platform team before any public deployment.
