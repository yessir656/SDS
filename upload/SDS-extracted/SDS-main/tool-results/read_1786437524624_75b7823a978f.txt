    23→### 0.2 Step-by-Step (fresh clone)
    24→
    25→```bash
    26→# 1. Clone the repository
    27→git clone <your-repo-url> sds-chem
    28→cd sds-chem
    29→
    30→# 2. Install dependencies with Bun (do NOT use npm install)
    31→bun install
    32→
    33→# 3. Create your environment file from the template
    34→cp .env.example .env
    35→
    36→# 4. Edit .env — set these values:
    37→#    - ADMIN_EMAIL         (your admin login email)
    38→#    - ADMIN_PASSWORD      (a strong password — will be bcrypt-hashed)
    39→#    - NEXTAUTH_SECRET     (generate one — see the comment in .env.example)
    40→#    - DATABASE_URL        (already set to ./db/custom.db — leave as-is)
    41→#    - NEXTAUTH_URL        (already http://localhost:3000 — leave as-is)
    42→#
    43→#    Generate a NEXTAUTH_SECRET with:
    44→#      bun -e 'console.log(require("crypto").randomBytes(32).toString("hex"))'
    45→
    46→# 5. Create the SQLite database + tables
    47→bun run db:push
    48→
    49→# 6. Seed the database:
    50→#    - Creates the admin user from ADMIN_EMAIL / ADMIN_PASSWORD
    51→#    - Imports the 14 seed chemicals
    52→#    - Generates a placeholder SDS PDF for each chemical
    53→bun run db:seed
    54→
    55→# 7. Start the dev server
    56→bun run dev
    57→```
    58→
    59→Open **http://localhost:3000** in your browser. You should see the chemical catalog with 14 chemicals.

    67→### 0.4 Why `npm run dev` doesn't work (and how to fix it)
    68→
    69→If you already ran `npm install` and `npm run dev`, you likely hit one of these:
    70→
    71→| Symptom | Cause | Fix |
    72→|---|---|---|
    73→| `npm run dev` fails with `tee: command not found` | Old script used a Unix-only `tee` pipe. **This has been fixed** — update to the latest code, or run `npx next dev -p 3000` directly. | `bun install` (or `npm install`) on latest code, then `bun run dev` |
    74→| `npm run db:seed` fails with `SyntaxError` or `Cannot find module` | The seed script is TypeScript run via Bun. Node/npm can't execute `.ts` files directly. | Install Bun, then run `bun run db:seed` |
    75→| App loads but shows "Database Error" / 0 chemicals | The database hasn't been created/seeded yet. | Run `bun run db:push && bun run db:seed` |
    76→| `PrismaClientInitializationError` | `DATABASE_URL` points to a path that doesn't exist on your machine. | Make sure `.env` has `DATABASE_URL=file:./db/custom.db` (relative path). Run `bun run db:push`. |
    77→| 401 on every admin API | `NEXTAUTH_SECRET` is missing or the `.env` wasn't loaded. | Set `NEXTAUTH_SECRET` in `.env`; restart `bun run dev`. |
    78→| Login fails with "Invalid email or password" | Admin user not created, or `.env` credentials don't match what's in the DB. | Run `bun run db:seed` again (it's idempotent — updates the admin to match `.env`). |

   134→## 2. High-Level Architecture
   135→
   136→```
   137→┌─────────────────────────────────────────────────────────────────┐
   138→│                        PUBLIC PWA  (/)                          │
   139→│  Catalog → Detail → Emergency views (single-route SPA, Zustand) │
   140→│  Offline-first: all reads go to Dexie (IndexedDB)               │
   141→│  Writes (favorites/notes/prefs) are LOCAL ONLY                  │
   142→└───────────────┬─────────────────────────────────┬───────────────┘
   143→                │ GET /api/sync?since=<ts>         │ GET /api/chemicals
   144→                │ GET /api/sds/[id]/download       │
   145→                ▼                                  ▼
   146→┌─────────────────────────────────────────────────────────────────┐
   147→│                     PUBLIC API (no auth)                        │
   148→│  /api/sync          delta sync (chemicals + SDS metadata)       │
   149→│  /api/chemicals     list / get chemical                         │
   150→│  /api/sds/[id]/download   stream SDS PDF                        │
   151→└───────────────┬─────────────────────────────────────────────────┘
   152→                │ Prisma
   153→                ▼
   154→┌─────────────────────────────────────────────────────────────────┐
   155→│                  PRISMA + SQLite  (source of truth)             │
   156→│  User · Chemical · SdsDocument                                  │
   157→└─────────────────────────────────────────────────────────────────┘
   158→                ▲
   159→                │ requireAdmin()  (server-side session check)
   160→┌───────────────┴─────────────────────────────────────────────────┐
   161→│                    ADMIN API (auth required)                    │
   162→│  /api/admin/dashboard          stats                            │
   163→│  /api/admin/chemicals          POST  (create)                   │
   164→│  /api/admin/chemicals/[id]     GET / PUT / DELETE               │
   165→│  /api/admin/sds                POST  (upload PDF)               │
   166→│  /api/admin/sds/[id]           DELETE (revert to placeholder)   │
   167→└───────────────┬─────────────────────────────────────────────────┘
   168→                ▲
   169→                │ NextAuth session (JWT, httpOnly cookie)
   170→┌───────────────┴─────────────────────────────────────────────────┐
   171→│                    ADMIN UI  (/admin)                           │
   172→│  /admin/login   sign-in form                                    │
   173→│  /admin         dashboard: Overview / Chemicals / SDS tabs      │
   174→│  Protected by src/middleware.ts (edge, role=ADMIN)              │
   175→└─────────────────────────────────────────────────────────────────┘
   176→```
   177→
   178→### Key principles
   179→- **Server is the source of truth** for chemical & SDS data. Client Dexie DB is a cache.
   180→- **Offline-first:** the public PWA reads from Dexie. It works fully offline after first sync.
   181→- **Delta sync:** clients ask for changes since their last sync timestamp — never the whole DB.
   182→- **SDS PDFs are versioned & cached** as Blobs in IndexedDB; only re-downloaded when version changes.
   183→- **User preferences (favorites/notes) stay local** — never sent to the server, never overwritten.
   184→- **Admin authorization is server-side** in every admin API route (`requireAdmin()`). The edge middleware is defense-in-depth only.

   291→| ghsPictograms | String | JSON-encoded `GhsPictogram[]` |

   296→| personalProtectiveEquipment | String | JSON array |
   297→| firstAidMeasures, firefightingMeasures, accidentalReleaseMeasures | String | SDS sections 4/5/6 |

   299→| createdAt, updatedAt | DateTime | |

   324→## 5. Client Database (Dexie v2)
   325→
   326→```
   327→chemicals      : ChemicalRecord  (keyPath: id)        + indexes on casNumber, department, etc.
   328→sdsDocuments   : SdsMeta          (keyPath: chemicalId)
   329→sdsBlobs       : { chemicalId, version, blob, fetchedAt }   ← SDS PDF Blob cache
   330→syncMeta       : { key, value }   ← lastSyncTimestamp, syncMutex, etc.
   331→locations      : LaboratoryLocation
   332→preferences    : UserPreferences  (favorites, notes, theme — LOCAL ONLY)
   333→```
   334→
   335→**Why two stores?** `sdsDocuments` holds metadata (small, synced as JSON). `sdsBlobs` holds the actual PDF Blob (large, only re-fetched when `version` changes).

   339→## 6. API Reference
   340→
   341→### Public (no auth)
   342→| Method | Path | Purpose |
   343→|---|---|---|
   344→| GET | `/api/sync?since=<epoch-ms>` | Delta sync. Returns `{ chemicals: [...], sdsDocuments: [...], deletedChemicalIds: [...], serverTime }`. Only records with `updatedAt > since` (or `deletedAt > since`) are returned. |
   345→| GET | `/api/chemicals` | List all non-deleted chemicals (metadata only, no PDF). |
   346→| GET | `/api/chemicals/[id]` | Single chemical. |
   347→| GET | `/api/sds/[id]/download` | Stream the SDS PDF for chemical `[id]`. Sets `Content-Type: application/pdf`. Used by both the public PWA (caches Blob) and admin "View". |
   348→
   349→### Admin (auth required — `requireAdmin()`)
   350→| Method | Path | Purpose |
   351→|---|---|---|
   352→| GET | `/api/admin/dashboard` | Stats: total chemicals, SDS coverage, department distribution, recent updates. |
   353→| POST | `/api/admin/chemicals` | Create chemical. Auto-creates a placeholder `SdsDocument`. Body validated by zod. |
   354→| GET | `/api/admin/chemicals/[id]` | Read single (admin view). |
   355→| PUT | `/api/admin/chemicals/[id]` | Update. Bumps `serverVersion`. Sets `updatedById`. |
   356→| DELETE | `/api/admin/chemicals/[id]` | Soft-delete (`deletedAt = now`). Cascade-soft-deletes the SDS. |
   357→| POST | `/api/admin/sds` | Upload / replace SDS PDF. Multipart form. Validates magic bytes + MIME + extension + size. Stores with UUID filename. Increments `version`, sets `status = available`. |
   358→| POST | `/api/admin/sds/extract` | **AI extraction.** Upload a PDF → returns structured chemical fields extracted by VLM. Does NOT store the PDF. See [§ 6.1 AI SDS Extraction Pipeline](#61-ai-sds-extraction-pipeline) below. |
   359→| DELETE | `/api/admin/sds/[id]` | Revert to placeholder. Removes the uploaded file, resets `status = placeholder`, increments `version`. |
   360→
   361→### 6.1 AI SDS Extraction Pipeline
   362→
   363→`POST /api/admin/sds/extract` — AI-powered auto-fill for the chemical form.
   364→
   365→**Flow:**
   366→```
   367→Admin uploads PDF
   368→       ↓
   369→[1] Validate: magic bytes (%PDF-), MIME (application/pdf), extension (.pdf), size (≤10MB)
   370→       ↓
   371→[2] Save PDF to os.tmpdir()/sds-extract-{uuid}.pdf
   372→       ↓
   373→[3] pdftoppm -png -r 150 -l 5  (converts first 5 pages to PNG images)
   374→       ↓
   375→[4] Read each PNG as base64
   376→       ↓
   377→[5] zai.chat.completions.createVision()  (send all page images in one call)
   378→     Prompt asks for JSON with 15 fields + provides valid enum values
   379→     for signalWord, ghsPictograms, hazardClasses so VLM maps correctly
   380→       ↓
   381→[6] Parse VLM response: strip markdown fences, JSON.parse, fallback extraction
   382→       ↓
   383→[7] Sanitize: filterValid() drops invalid enum IDs, default signalWord="danger"
   384→       ↓
   385→[8] Clean up: delete temp PDF + all temp PNGs (finally block)
   386→       ↓
   387→Return { success: true, data: { ...15 fields } }
   388→```
   389→
   390→**Response shape:**
   391→```json
   392→{
   393→  "success": true,
   394→  "data": {
   395→    "chemicalName": "Toluene",
   396→    "casNumber": "108-88-3",
   397→    "formula": "C₇H₈",
   398→    "tradeName": "Methylbenzene",
   399→    "manufacturer": "Sigma-Aldrich",
   400→    "supplier": "...",
   401→    "signalWord": "danger",
   402→    "ghsPictograms": ["flame", "health-hazard", "exclamation-mark"],
   403→    "hazardClasses": ["flammable", "irritant", "reproductive-toxicant", "specific-target-organ-toxicity"],
   404→    "storageLocation": "",
   405→    "safetyInstructions": "...",
   406→    "emergencyContact": "...",
   407→    "personalProtectiveEquipment": ["Chemical splash goggles", "Nitrile gloves", "..."],
   408→    "firstAidMeasures": "...",
   409→    "firefightingMeasures": "...",
   410→    "accidentalReleaseMeasures": "..."
   411→  }
   412→}
   413→```
   414→
   415→**Key files:**
   416→- `src/app/api/admin/sds/extract/route.ts` — the API endpoint
   417→- `src/components/admin/chemical-manager.tsx` — the frontend `handleAutoFill()` function + "Auto-fill from PDF" button + review banner
   418→
   419→**System dependency:** `pdftoppm` (from poppler-utils) must be installed on the server. Already available in the sandbox; for production deployments, install via `apt-get install poppler-utils` (Debian/Ubuntu) or `brew install poppler` (macOS).
   420→
   421→**Cost:** Free — uses the in-house `z-ai-web-dev-sdk` VLM service. Each extraction uses ~3,000-10,000 tokens depending on PDF length.

   431→## 7. Sync Engine (`src/lib/sync-engine.ts`)
   432→
   433→### Trigger points
   434→1. **App startup** — fires once Dexie is initialized.
   435→2. **Offline → online transition** — `use-online-status` hook notifies the engine.
   436→3. **Periodic** — runs every few minutes while online.
   437→
   438→### Algorithm
   439→```
   440→1. Acquire mutex (in Dexie.syncMeta) — prevents concurrent syncs across tabs.
   441→2. Read lastSyncTimestamp from syncMeta.
   442→3. GET /api/sync?since=<lastSyncTimestamp>.
   443→4. For each chemical in response:
   444→   - If deleted (deletedAt > since) → remove from Dexie.chemicals.
   445→   - Else → upsert into Dexie.chemicals.
   446→5. For each sdsDocument in response:
   447→   - Upsert metadata into Dexie.sdsDocuments.
   448→   - Compare version with Dexie.sdsBlobs.
   449→     - If version unchanged AND blob exists → skip (no re-download).
   450→     - If version changed OR blob missing → GET /api/sds/[id]/download,
   451→       store Blob in Dexie.sdsBlobs with new version.
   452→6. Persist new lastSyncTimestamp = response.serverTime.
   453→7. Release mutex. Update Zustand sync status.
   454→```
   455→
   456→### Rate limiting
   457→A minimum interval between sync attempts prevents hammering the server on flaky connections. Manual retry from the UI bypasses the interval once.
   458→
   459→### Status states (the `SyncStatus` type)
   460→| State | Meaning |
   461→|---|---|
   462→| `offline` | Navigator reports offline. No sync attempts. |
   463→| `syncing` | A sync is in progress. |
   464→| `synced` | Last sync completed successfully and we're online. |
   465→| `local-changes` | *(reserved)* user has local-only changes that couldn't be pushed (currently preferences only — always local). |
   466→| `error` | Last sync attempt failed. UI shows a retry button. |
   467→
   468→### Conflict resolution
   469→- **Chemical / SDS data:** server-wins. The latest `updatedAt` always wins.
   470→- **User preferences / favorites / notes:** local-only, never synced, never overwritten.

   474→## 8. Security Model
   475→
   476→### Authentication
   477→- NextAuth Credentials provider.
   478→- Passwords hashed with **bcrypt (12 rounds)** — never stored or logged in plaintext.
   479→- JWT session strategy, 30-day max age.
   480→- Cookies: `httpOnly`, `sameSite=lax`, `secure` in production (`__Secure-` prefix).
   481→
   482→### Authorization (defense in depth)
   483→1. **Edge middleware** (`src/middleware.ts`) — blocks `/admin/*` (except `/admin/login`) unless the JWT has `role === "ADMIN"`. Fast, runs at the edge.
   484→2. **Server-side guard** (`requireAdmin()` in `src/lib/session.ts`) — every admin API route calls this. Returns 401 if no valid admin session. This is the real enforcement layer; the middleware is just a UX optimization / defense-in-depth.
   485→
   486→### SDS file upload safety
   487→- **Magic-byte validation** — the file must start with `%PDF-` (PDF signature). Renamed non-PDFs are rejected.
   488→- **MIME type check** — must be `application/pdf`.
   489→- **Extension check** — must end in `.pdf`.
   490→- **Size limit** — enforced (see `validation.ts`).
   491→- **Filename handling** — user-supplied filename is stored only for display/download. The actual stored file is named `<uuid>.pdf` under `storage/`. No path traversal possible.
   492→- **No path exposure** — `storageKey` is a UUID, never the original path.
   493→
   494→### Input validation
   495→- All admin chemical inputs validated with **zod** schemas before reaching Prisma.
   496→- Prisma parameterizes all queries — no raw SQL, no SQL injection surface.
   497→
   498→### Security headers (`next.config.ts`)
   499→- Content-Security-Policy
   500→- X-Frame-Options: DENY
   501→- X-Content-Type-Options: nosniff
   502→- Referrer-Policy
   503→- Strict-Transport-Security (HSTS)
   504→- Permissions-Policy
   505→
   506→### Secrets
   507→- `NEXTAUTH_SECRET` — required in production. Generate with:
   508→  ```bash
   509→  bun -e 'console.log(require("crypto").randomBytes(32).toString("hex"))'
   510→  ```
   511→- `ADMIN_PASSWORD` — plaintext in `.env` only; hashed before DB storage.
   512→- `.env` is gitignored. `.env.example` is the committed template.
   513→
   514→### Known platform-level caveat
   515→The sandbox gateway (`Caddyfile`) uses an `XTransformPort` query param for port routing. This is an open-proxy-style SSRF surface at the **infra level** and is outside the application code. Flag for the platform team before any public deployment.

   648→## 14. Troubleshooting (Developer)
   649→
   650→| Symptom | Cause | Fix |
   651→|---|---|---|
   652→| `PrismaClientInitializationError` | DB file missing or path wrong | Check `DATABASE_URL` in `.env`; run `bun run db:push` |
   653→| `bun run db:seed` does nothing | Admin already exists with same email | It's idempotent — it upserts. Check `SELECT * FROM User`. |
   654→| 401 on every admin API even when "logged in" | Session cookie not sent (cross-origin / different port) | Ensure requests use relative paths; in this sandbox use `XTransformPort` for cross-service calls |
   655→| SDS upload 413 | File too large | Check the size limit in `src/lib/validation.ts` / reverse proxy |
   656→| Dexie schema version conflict | Old client DB version | Bump Dexie schema version in `src/lib/local-db.ts` with an upgrade function |
   657→| Service worker not updating | Old SW cached | Bump `CACHE_VERSION` in `public/sw.js`; user will get new SW on next load |
   658→| Preview shows blank "Z" screen | Dev server not running | `bun run dev` (this is the most common "it's loading" report) |
